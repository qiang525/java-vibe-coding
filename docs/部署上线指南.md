# 部署上线指南

> 本文讲清楚：**怎么把本项目从"本地能跑"变成"服务器上能访问"**。
> 阅读顺序建议：先看第一节理解整体，再看后面按步骤操作。

---

## 一、先理清：上线到底做了什么

本地开发时，你的电脑上跑着三个东西：

```
浏览器 → 前端(5173) → 后端(8080) → MySQL(3306) + Redis(6379)
```

上线之后，架构变成这样：

```
用户浏览器
    ↓ 80/443 端口
  Nginx（唯一入口）
    ├── 静态文件  → 前端构建产物（HTML/CSS/JS）
    └── /api/**  → 后端(8080) → MySQL + Redis
```

**关键变化**：Nginx 成了统一的"大门"。

为什么需要它？三个原因：

| 原因 | 说明 |
|---|---|
| **解决跨域** | 前端和接口同源，浏览器不再拦截 |
| **统一入口** | 只暴露 80/443 一个端口，后端 8080 不对外 |
| **性能** | 静态文件由 Nginx 直接返回，比 Java 快得多；还能开 gzip |

## 二、部署前准备

### 2.1 服务器要求

| 项目 | 最低 | 建议 |
|---|---|---|
| CPU | 2 核 | 2 核 |
| 内存 | 2 GB | 4 GB |
| 磁盘 | 20 GB | 40 GB（要存上传的文件） |
| 系统 | Linux（Ubuntu 20.04+ / CentOS 7+） | Ubuntu 22.04 |

### 2.2 需要装的东西

**方案一：Docker 部署（推荐）**

```bash
# Ubuntu 安装 Docker
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 验证
docker --version
docker compose version
```

**方案二：传统部署**

```bash
# JDK 11
sudo apt install openjdk-11-jdk -y

# MySQL 8.0
sudo apt install mysql-server -y

# Redis
sudo apt install redis-server -y

# Nginx
sudo apt install nginx -y

# Node（只在服务器上构建前端时才需要）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install nodejs -y
```

## 三、方案一：Docker 部署（推荐）

### 第 1 步：把代码传到服务器

```bash
# 方式 A：从 GitHub 拉
git clone <你的仓库地址> coursehub
cd coursehub

# 方式 B：本地打包上传
# 本地执行：
#   tar -czf coursehub.tar.gz --exclude=node_modules --exclude=target --exclude=.git .
#   scp coursehub.tar.gz user@服务器IP:~/
# 服务器上执行：
#   tar -xzf coursehub.tar.gz -C coursehub
```

### 第 2 步：配置环境变量

```bash
cd deploy
cp .env.example .env
vim .env        # 或 nano .env
```

**把三个密码改成你自己的**：

```ini
MYSQL_ROOT_PASSWORD=你的强密码1
REDIS_PASSWORD=你的强密码2
JWT_SECRET=至少32位随机字符串
```

> **生成随机密钥的方法**：
> ```bash
> openssl rand -base64 48
> ```
>
> ⚠️ **这三个值绝对不能提交到 Git**。项目已经把 `deploy/.env` 加进 `.gitignore` 了。

### 第 3 步：一键启动

```bash
cd ..      # 回到项目根目录
docker compose -f deploy/docker-compose.prod.yml up -d
```

第一次启动会：下载镜像 → 构建前后端 → 启动四个容器。**大约 5-10 分钟**。

### 第 4 步：看启动状态

```bash
# 看容器状态，四个都应该是 Up (healthy)
docker compose -f deploy/docker-compose.prod.yml ps

# 看后端日志（等出现 Started CourseHubApplication 就是成功了）
docker compose -f deploy/docker-compose.prod.yml logs -f backend
```

### 第 5 步：验证

```bash
# 在服务器上测
curl http://localhost/api/health

# 期望输出：
# {"code":0,"message":"服务运行正常","data":{"status":"UP",...}}
```

然后浏览器打开 `http://服务器IP`，应该能看到首页。

## 四、方案二：传统部署（不用 Docker）

### 第 1 步：初始化数据库

```bash
mysql -uroot -p < backend/sql/schema.sql
mysql -uroot -p coursehub < backend/sql/init_data.sql

# 建议：为应用单独建一个账号，不要直接用 root
mysql -uroot -p -e "
CREATE USER 'coursehub'@'localhost' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON coursehub.* TO 'coursehub'@'localhost';
FLUSH PRIVILEGES;"
```

### 第 2 步：构建后端

```bash
cd backend
mvn clean package -DskipTests
# 产物：target/coursehub-1.0.0.jar
```

### 第 3 步：构建前端

```bash
cd frontend
npm ci
npm run build
# 产物：dist/ 目录
```

### 第 4 步：配置后端环境变量

```bash
sudo mkdir -p /opt/coursehub
sudo cp backend/target/coursehub-1.0.0.jar /opt/coursehub/
sudo mkdir -p /opt/coursehub/upload
```

创建 `/opt/coursehub/env.sh`：

```bash
export SPRING_PROFILES_ACTIVE=prod
export SPRING_DATASOURCE_URL="jdbc:mysql://localhost:3306/coursehub?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true"
export SPRING_DATASOURCE_USERNAME=coursehub
export SPRING_DATASOURCE_PASSWORD=你的数据库密码
export SPRING_REDIS_HOST=localhost
export SPRING_REDIS_PORT=6379
export JWT_SECRET=你的至少32位随机密钥
export COURSEHUB_FILE_LOCAL_PATH=/opt/coursehub/upload
export COURSEHUB_FILE_TEMP_PATH=/opt/coursehub/upload/temp
```

### 第 5 步：做成系统服务（开机自启）

创建 `/etc/systemd/system/coursehub.service`：

```ini
[Unit]
Description=CourseHub Backend
After=network.target mysql.service redis-server.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/coursehub
EnvironmentFile=/opt/coursehub/env.sh
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/coursehub/coursehub-1.0.0.jar
Restart=always
RestartSec=10
StandardOutput=append:/var/log/coursehub/app.log
StandardError=append:/var/log/coursehub/app.log

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo mkdir -p /var/log/coursehub
sudo chown www-data:www-data /var/log/coursehub /opt/coursehub/upload
sudo systemctl daemon-reload
sudo systemctl enable --now coursehub
sudo systemctl status coursehub      # 看状态
sudo journalctl -u coursehub -f      # 看实时日志
```

### 第 6 步：配置 Nginx

```bash
# 拷贝项目里的配置
sudo cp deploy/nginx.conf /etc/nginx/conf.d/coursehub.conf

# ⚠️ 传统部署时后端在宿主机上，要把 upstream 改成 127.0.0.1
sudo sed -i 's/server backend:8080;/server 127.0.0.1:8080;/' /etc/nginx/conf.d/coursehub.conf

# 拷贝前端构建产物
sudo mkdir -p /var/www/coursehub
sudo cp -r frontend/dist/* /var/www/coursehub/

# 改 root 路径
sudo sed -i 's|root /usr/share/nginx/html;|root /var/www/coursehub;|' /etc/nginx/conf.d/coursehub.conf

# 检查配置语法并重载
sudo nginx -t
sudo systemctl reload nginx
```

## 五、上线清单（逐项打勾）

### 上线前

- [ ] `.env` 里三个密码都改成强密码了
- [ ] `JWT_SECRET` 至少 32 位且是随机生成的
- [ ] 数据库已初始化（建表 + 种子数据）
- [ ] `application-prod.yml` 里没有硬编码的密码
- [ ] 服务器防火墙只开了 80 / 443 / 22

### 上线后验证

- [ ] `curl http://服务器IP/api/health` 返回 `code=0`
- [ ] 浏览器打开能正常显示首页
- [ ] **注册一个账号**（验证写数据库正常）
- [ ] **登录**（验证 JWT 正常）
- [ ] **创建课程**（验证写操作正常）
- [ ] **上传一个文件**（验证文件存储正常）
- [ ] **下载刚上传的文件**（验证读取正常）
- [ ] **搜索**（验证全文检索正常，Redis 正常）
- [ ] 重启容器后**文件还在**（验证数据卷挂载正确）

### 安全检查

- [ ] `/doc.html` 接口文档在生产环境已关闭或加访问限制
- [ ] 数据库 3306、Redis 6379 **不对外暴露**（只监听内网）
- [ ] 日志里**不打印密码、Token**
- [ ] 已配置 HTTPS（下一步）

## 六、配置 HTTPS（有域名后）

### 用 Let's Encrypt 免费证书

```bash
sudo apt install certbot python3-certbot-nginx -y

# 自动申请并配置（把 example.com 换成你的域名）
sudo certbot --nginx -d example.com -d www.example.com

# 自动续期（certbot 已自动加了定时任务，验证一下）
sudo certbot renew --dry-run
```

证书会自动装到 `/etc/letsencrypt/live/example.com/`。

然后在 Nginx 配置里启用 HTTPS 的 server 块（`deploy/nginx.conf` 底部有现成模板）。

## 七、日常运维

### 看日志

```bash
# Docker 部署
docker compose -f deploy/docker-compose.prod.yml logs -f backend
docker compose -f deploy/docker-compose.prod.yml logs -f frontend

# 传统部署
sudo journalctl -u coursehub -f
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

### 备份数据库

```bash
# 手动备份
docker exec coursehub-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" coursehub \
  > backup/coursehub_$(date +%Y%m%d_%H%M%S).sql

# 恢复
docker exec -i coursehub-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" coursehub \
  < backup/coursehub_20261009_120000.sql
```

**建议**：加个 crontab 每天自动备份，并保留最近 7 天。

```bash
crontab -e
# 加这一行：每天凌晨 2 点备份
0 2 * * * cd /opt/coursehub && docker exec coursehub-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" coursehub > backup/auto_$(date +\%Y\%m\%d).sql
```

### 更新发布

```bash
# 1. 拉最新代码
git pull

# 2. 重新构建并重启（只重建变化的服务）
docker compose -f deploy/docker-compose.prod.yml up -d --build

# 3. 看日志确认启动成功
docker compose -f deploy/docker-compose.prod.yml logs -f backend
```

### 回滚

```bash
# 1. 看提交历史，找到要回滚到的版本
git log --oneline

# 2. 切回去
git checkout <commit-id>

# 3. 重新构建
docker compose -f deploy/docker-compose.prod.yml up -d --build
```

> ⚠️ **回滚前必须确认**：这次发布有没有改数据库结构？
> 如果加了字段，回滚代码后新字段仍然存在（一般不会有问题）；
> 如果**删了字段**，回滚会有问题 —— 所以生产环境**尽量避免删字段**，
> 改成"先停止使用、观察一段时间再删"。

## 八、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 打开页面 502 | 后端没起来 | `docker compose logs backend` 看报错 |
| 上传文件报 413 | Nginx 限制 | 确认 `client_max_body_size 600M` 已配 |
| 上传大文件超时 | 超时太短 | 确认 `proxy_read_timeout 300s` |
| 数据库连不上 | 密码错 / 容器没起来 | 检查 `.env` 与容器健康状态 |
| 登录后立即失效 | JWT_SECRET 每次重启都变 | 把它固定写在 `.env` 里 |
| 重启后文件全没了 | 没挂数据卷 | 确认 `coursehub_upload` 卷已挂载 |
| 时间差 8 小时 | 时区没设 | 确认容器 `TZ=Asia/Shanghai` |
| 中文乱码 | 字符集不对 | 确认 MySQL 是 `utf8mb4` |

## 九、性能与安全建议（进阶）

| 方向 | 做法 |
|---|---|
| **数据库** | 给热点查询加索引；开启慢查询日志，定期用 `EXPLAIN` 检查 |
| **缓存** | 热点数据（搜索热词、热门资料）放 Redis，设合理过期时间 |
| **静态资源** | 交给 CDN；Nginx 开 `sendfile on; tcp_nopush on;` |
| **连接池** | Druid 连接池大小按 `CPU核数*2 + 磁盘数` 估算，别盲目调大 |
| **日志** | 用 logrotate 定期切割，避免日志文件把磁盘撑满 |
| **监控** | 至少要监控：服务存活、接口耗时、错误率、磁盘使用率 |
| **限流** | 登录、上传等接口加限流，防刷 |
| **安全** | 定期更新依赖修复漏洞；数据库、Redis 只监听内网 |

## 十、本地模拟生产环境（不上服务器也能验证）

如果你想先在本地确认部署配置没问题：

```bash
cd D:/桌面/Java项目AIGC/deploy
cp .env.example .env      # 改成你自己的密码
cd ..
docker compose -f deploy/docker-compose.prod.yml up -d --build
```

启动后访问 `http://localhost` 即可。

> ⚠️ **本机没装 Docker**。要用这个方案得先装 Docker Desktop，
> 并且要确认 Docker 的数据目录不在 C 盘（Docker Desktop 设置里可以改）。
