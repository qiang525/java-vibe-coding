# CourseHub 零基础学习路线图

> **写这份文档的前提**：你说自己"啥也不懂"，不是谦虚，是实情 ——
> 大学教的是 20 年前的知识点，而"怎么用电脑做东西"这一层从来没人教。
>
> **这份文档不是教程**，是**路线**。它回答三个问题：
> ① 我现在在哪？ ② 下一步该干什么？ ③ 什么算学会了？
>
> **你现在不需要学。** 先把这份文档放着。等你哪天有 30 分钟，
> 从「方案 A」开始，一次只做一小步。

## 一、先给你一个确定性：搁置半年也不会坏

你担心"没时间管理，项目会不会废掉"——**不会**。

| 你可能担心的 | 实际情况 |
|---|---|
| 代码会不会丢 | 在 `D:\桌面\Java项目AIGC`，而且已经提交到 Git，还有 GitHub 远程仓库 |
| 数据库会不会乱 | 一条命令重建：`backend\sql\init_all.sql`（会删库重来，是设计好的） |
| 忘了怎么启动 | `tools\` 里有 3 个双击脚本，说明书在第 ② 册 |
| 上传的资料会不会丢 | 在 `backend\upload\`。真要保命就用 `tools\backup-db.bat` 备份数据库 |
| 环境变量会不会被改坏 | `tools\check-env.bat` 一跑就知道哪项不对 |

**半年后回来，只需要 4 步**：

```
1. 双击 tools\check-env.bat          ← 看 5 项是否正常
2. 双击 tools\start-redis.bat        ← 等 Ready to accept connections
3. 双击 tools\start-backend.bat      ← 等 Started CourseHubApplication
4. 浏览器打开 http://localhost:8080  ← admin / Demo123456
```

**这 4 步写在 `02-启动项目.md` 里，也写在下面第五节。丢不了。**

## 三、路线总览

六个阶段，**从"会用电脑"到"能独立做出下一个项目"**。

```
阶段0 地基      阶段1 会看     阶段2 会跑      阶段3 看请求    阶段4 读代码    阶段5 会改      阶段6 上线
3-5 小时   →   2 小时    →   3 小时    →   6 小时    →   10 小时   →   15 小时   →   8 小时
   ↓             ↓             ↓              ↓              ↓             ↓             ↓
懂路径/端口   能介绍项目     能独立启动     看得懂F12      顺藤摸瓜      加个功能      有公网地址
```

| 阶段 | 名字 | 目标（一句话） | 材料 | 大约 |
|---|---|---|---|---|
| **0** | 地基 | 不再被"路径/命令行/端口"卡住 | `手把手教学/07-电脑基本功.md` | 3-5 h |
| **1** | 会看 | 能向同学介绍这个网站是干什么的 | `00-先认识这些文件.md` + `03-功能走查.md` | 2 h |

## 四、每个阶段展开：做什么、怎么算学会

### 阶段 0 · 地基（3-5 小时）

**为什么先做这个**：后面的每一步都会用到"路径""命令行""端口"。
地基不牢，你会在第 2 册就卡住，然后放弃。

**学什么**（`07-电脑基本功.md`，10 节）：

| 节 | 内容 | 为什么必须懂 |
|---|---|---|
| 一 | 文件、文件夹、路径、四个盘符 | 后面所有"打开某个文件"都靠它 |
| 二 | 文件操作四件套 + 两个坑 | 你会不停新建/改名/删除文件 |
| 三 | 压缩包与解压 | 以后下载任何素材都要用 |
| 四 | 命令行 + `cd`/`dir`/PATH | 启动脚本、排错全靠它 |
| 五 | 进程与任务管理器 | "关了怎么还在跑" |
| 六 | 端口 + `netstat`/`taskkill` | "8080 被占用"是最高频故障 |
| 七 | 浏览器 F12 | 前端排错的唯一入口 |
| 八 | 环境变量 PATH | "命令找不到"的根因 |
| 九 | 十个快捷键 | 效率翻倍 |

**怎么算学会**（能做出来，不是"看过"）：

- [ ] 能在 `D:\桌面` 下新建文件夹，用命令行 `cd` 进去，`dir` 看到自己建的文件
- [ ] 能查出 3306 端口被哪个进程占着
- [ ] 能打开 F12，在 Console 里找到一条红色报错并读出它的意思
- [ ] 第 7 册末尾的 10 个自检题，能答对 8 个

---

### 阶段 1 · 会看（2 小时，不写一行代码）

**目标**：能向同学解释"这个网站是干什么的、有哪几个功能"。

**怎么做**：

1. 读 `00-先认识这些文件.md`（20 分钟）—— 知道 `.bat`/`.yml`/`.md` 是什么
2. 读完 `README.md` 的前三节（20 分钟）—— 知道项目定位和能力清单
3. 按 `03-功能走查.md` 走一遍（60 分钟）—— 需要先按阶段 2 把网站跑起来

> ⚠️ 顺序上阶段 1 和 2 会交叉：**走查需要网站是活的**。
> 所以实操顺序是：阶段 0 → 阶段 2（启动）→ 阶段 1（走查）。
> 文档这么排是因为"先知道是什么，再动手"更不容易懵。

**怎么算学会**：

- [ ] 不看文档，能自己完成：登录 → 进课程 → 上传一个文件 → 搜到它 → 下载 → 评论
- [ ] 能说出"资料"和"课程"是什么关系（一对多）
- [ ] 能说出"可信度评分"大致是怎么算的（5 个因子加权）

---

### 阶段 2 · 会跑（3 小时）

**目标**：**冷启动**。也就是把一切关掉，从零开始，5 分钟内让网站能登录。

**怎么做**：

1. `01-环境准备.md` 第 1-7 节（60 分钟）—— 逐项检查环境，做自检表
2. `02-启动项目.md` 第 1-4 节（60 分钟）—— 启动 Redis + 后端 + 打开浏览器
3. 故意制造 3 个错误，再修好（60 分钟）：
   - 不启动 Redis 就启动后端 → 看报什么错 → 按 `06-故障排查.md` F03 修
   - 把 `application-local.yml` 的密码改错 → 看报什么错 → 按 F04 修
   - 启动两次后端 → 看 `Port 8080 was already in use` → 按 F02 修

> **故意犯错是学得最快的方式。** 因为你迟早会遇到，与其慌，不如先演练一遍。

**怎么算学会**：

- [ ] 从"电脑刚开机"到"浏览器登录成功"，全程不查文档，5 分钟内完成
- [ ] 能说出启动顺序为什么是 MySQL → Redis → 后端
- [ ] 遇到"后端起不来"，知道先看 IDEA 的 Run 面板最后 20 行

---

### 阶段 3 · 看请求（6 小时）

**目标**：说清**"我点了一下登录按钮，然后发生了什么"**。

这是从"使用者"变成"开发者"的分水岭。

**怎么做**：

1. `05-数据库与接口.md` 第一部分（2 小时）—— 用 IDEA 连上数据库，跑 6 条 SQL
2. `05-数据库与接口.md` 第二部分（2 小时）—— 打开 `/doc.html`，调 3 个接口
3. F12 抓包练习（2 小时）：
   - 抓登录请求，读出：URL、方法、请求体、状态码、响应里的 token
   - 抓课程列表请求，看 `?page=1&pageSize=10` 是怎么变成 `{list, total}` 的
   - 故意传一个错密码，看返回的 `code` 是多少

**怎么算学会**：

- [ ] 能在 F12 的 Network 里抓到任意一个接口请求，并说出它的四个要素
- [ ] 能用 Postman/curl/`doc.html` 三种方式之一，带 token 调通 `/api/auth/me`
- [ ] 能解释：为什么浏览器地址栏输入 `localhost:8080` 就能看到网页

---

### 阶段 4 · 读代码（10 小时）

**目标**：**顺藤摸瓜**。从一个 URL，找到它经过的每一个文件。

这是最像"程序员"的一步，也是最能建立信心的一步 —— 因为你会发现代码没有想象中那么神秘。

**怎么做**：

选一个最简单的接口练手：`GET /api/courses`（课程列表）

```
第 1 步：打开 CourseController.java，找到 list() 方法
        → 它调用了 courseService.page(query)

第 2 步：Ctrl + 点击 page，跳进 CourseServiceImpl.java
        → 里面有业务逻辑、参数校验、调用 mapper

第 3 步：Ctrl + 点击 mapper，跳进 CourseMapper.java（只有接口声明）

第 4 步：打开 resources/mapper/CourseMapper.xml
        → 真正的 SQL 在这里

第 5 步：把 SQL 复制到数据库里跑一遍，对比返回结果
```

**这条链就是后端开发的全部套路**：Controller → Service → Mapper → SQL。

后面所有接口都是这五步。练熟 3 个接口，你就"会读"了。

**怎么算学会**：

- [ ] 能不看文档，把 `/api/resources/{id}` 从 Controller 一路跟到 SQL
- [ ] 能说出 `entity` / `dto` / `vo` 三个目录的区别（为什么不能只用 entity）
- [ ] 能指出"三级可见性"的校验代码在哪个方法里

---

### 阶段 5 · 会改（15 小时）

**目标**：自己加一个功能，从数据库到页面全走通。

**为什么选"个人中心"**：它是最小的完整闭环 ——
加 2 个接口 + 1 个页面，涉及"前端 → 后端 → 数据库"三层，但逻辑简单。

**怎么做**（`docs/项目体检报告.md` 的 R4）：

```
1. 前端：新建 views/Profile.vue，做一个表单（昵称、密码）
2. 路由：router/index.js 加一条 /profile
3. 接口：api/user.js 加 updateProfile / changePassword
4. 后端：UserController 加两个 @PutMapping
5. 后端：UserServiceImpl 里写更新逻辑（BCrypt 加密新密码）
6. 数据库：不需要建表，sys_user 已有字段
7. 联调：F12 看请求 → 看返回 → 页面提示成功
8. 打包：build-to-backend.bat → 重启后端 → 8080 验证
```

**怎么算学会**：

- [ ] 改完昵称，刷新页面还是新昵称（说明真的存进数据库了）
- [ ] 改完密码，退出重登能用新密码（说明 BCrypt 加密对了）
- [ ] 整个过程中，你能自己定位 90% 的报错

> 做到这一步，你已经能独立做一个小项目了。
> 下一个项目不会再需要别人从头带你。

---

### 阶段 6 · 上线（8 小时）

**目标**：有个公网地址，发给同学就能打开。

**材料**：`docs/部署上线指南.md`

**需要额外准备**：一台云服务器（学生机一年几百块）、一个域名（可选）。

> 这一步建议放到最后。因为它需要花钱、需要接触 Linux，
> 而且**本地跑通已经能证明你会了**。不着急。

## 五、没时间怎么办：三种方案，按你的现实选

### 方案 A · 保住火苗（推荐给现在的你）

> **每周 30 分钟，只做阶段 0 和 2。**
> 目标不是学会，是**别掉队**：任何时候都能把网站打开演示给别人看。

| 周 | 做什么 | 多久 |
|---|---|---|
| 第 1 周 | 读 `07-电脑基本功.md` 第一~四节（路径、文件、压缩包、命令行） | 30 分钟 |
| 第 2 周 | 读第五节~第九节 + 做自检题 | 30 分钟 |
| 第 3 周 | 按 `02-启动项目.md` 走一遍：启动 → 打开 → 登录 | 30 分钟 |
| 第 4 周 | 关掉一切，自己冷启动一次（不看文档） | 30 分钟 |
| 之后每周 | **只做一件事**：双击 3 个 bat，打开 8080 点 5 分钟 | 5 分钟 |

**"每周 5 分钟"这一条最重要。** 它保证你手不生。
一周不碰就忘一半，这是所有人的通病，不是你的问题。

### 方案 B · 稳步推进（每周 2 小时，约 6 个月）

```
阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 →（阶段 4 选做）
每周 2 小时，每个阶段拆成 2-3 次
```

**关键**：每次开始前，先花 5 分钟复述"上次学到哪、这次要干什么"。
写在手机备忘录里就行。

### 方案 C · 假期冲刺（每天 3-4 小时，10-14 天）

```
第 1 天：阶段 0（地基）
第 2 天：阶段 2（启动）+ 阶段 1（走查）
第 3-4 天：阶段 3（F12 + 数据库 + 接口）
第 5-7 天：阶段 4（读 3 个接口的代码）
第 8-12 天：阶段 5（做个人中心）
第 13-14 天：阶段 6（部署，可选）
```

**关键**：每天结束前，用 5 分钟写三行笔记：
"今天做了什么 / 卡在哪 / 明天第一步"。三天后回头看，这三行能救命。

## 六、明确"不要学什么"（这一节能救你）

新手最大的坑不是学不会，是**一开始学太多**，然后放弃。

### 现阶段不要碰

| 别学 | 为什么 | 什么时候再学 |
|---|---|---|
| **数据结构与算法** | 跟"做出一个网站"没关系。你现在需要的是"能跑通"的正反馈 | 阶段 5 之后，想刷题/竞赛时 |
| **设计模式** | 23 种模式，你现在一个都用不上 | 做过 2 个项目后 |
| **Spring 源码** | 读源码需要有"用过"的底子，否则全是天书 | 工作 1 年后 |
| **背注解** | `@Autowired` `@Service` 是查的，不是背的 | 用多了自然会 |
| **另一门语言** | 同时学 Java 和 Python = 两个都学不会 | 这个项目能改功能之后 |
| **买课 / 囤资料** | 你已经有 13 份文档 + 一个真项目，比任何课都实在 | 卡住了再说 |

### 现阶段该做的只有一件

**把这一条链路走通一次**：

```
打开网页 → 点按钮 → 请求到后端 → 后端查数据库 → 返回 → 页面变了
```

走通一次，你对"Web 开发"的理解会超过看十本书。

## 七、什么算"学会了"：五个里程碑

不要用"我好像懂了"判断，用**能不能做出来**判断。

| 里程碑 | 具体动作 | 对应的阶段 |
|---|---|---|
| M1 会启动 | 冷启动到登录成功，5 分钟内，不看文档 | 阶段 0-2 |
| M2 会排错 | 故意弄坏 Redis / 密码 / 端口，都能自己修好 | 阶段 2 |
| M3 会看请求 | F12 抓一个请求，说出 URL/方法/请求体/响应 | 阶段 3 |
| M4 会读代码 | 从任何一个 URL 找到它对应的 SQL | 阶段 4 |
| M5 会改功能 | 自己加的页面能跑通，数据真的存进数据库 | 阶段 5 |

**M5 达成 = 你已经能独立做小项目了。**
这时候再去学算法、设计模式，才有意义 —— 因为你知道它们能解决什么问题。

## 八、四个必卡点，以及怎么过去

这四个坎，90% 的人都会遇到。**提前知道，就不会以为自己笨。**

### 卡点 1 ·「第 2 天就在环境上卡死」

**表现**：Redis 起不来、8080 被占用、Maven 下载卡住，半天没进展，觉得"我不适合"。

**真相**：环境问题是所有人的第一道坎，跟天赋无关。我这边也踩了三次 Redis 的坑。

**对策**：
- 别自己硬啃，直接翻 `06-故障排查.md`，25 个故障按现象分类
- 每个故障都有"现象 → 原因 → 一步步修"，照抄就行
- 实在不行，把报错**截图**发给我

### 卡点 2 ·「看的时候懂，合上就忘」

**表现**：看完文档觉得明白了，第二天什么都想不起来。

**真相**：这不是记性问题，是**"看"代替了"做"**。所有技能都是肌肉记忆。

**对策**：
- 每份文档只看它那节的「现在试一下」，**做了才算看完**
- 不记"是什么"，只记"去哪儿查"（比如：不记 25 个故障，只记"故障看第 6 册"）
- 允许自己忘 —— 忘了再查一遍，第二次会快很多

### 卡点 3 ·「不知道做这些有什么用」

**表现**：跟着做完了，但不知道意义在哪，动力下降。

**真相**：因为你在做别人设计好的步骤，没有"自己的目标"。

**对策**：给自己一个**真实的小目标**，比如：
- 把我们班的课程资料整理上去，发给同学用
- 给社团做一个报名页面
- 把这个项目改成"社团资料库"

**有目标的时候，学习速度会翻倍。**

### 卡点 4 ·「一周没碰，就彻底放下了」

**表现**：忙了一周，回来发现忘了大半，于是更不想碰了。

**真相**：这是最危险的一个坎，不是能力问题，是**启动成本**问题。

**对策**：设一个**最小维持动作**：

> 每周固定一个时间（比如周三晚 9 点），双击 3 个 bat，打开 8080 点 5 分钟，关掉。

- 只要 5 分钟，不需要学任何新东西
- 目的是保持"这是我能掌控的东西"的感觉
- 这一条坚持下来，你就不会掉队
