## 0. 先分清两个"网站"

| | 地址 | 从哪来 | 改代码后 |
|---|---|---|---|
| **A. 生产版** | `http://localhost:8080` | 后端托管的**打包好的**静态文件 | **不会自动变**，必须重新打包 |
| **B. 开发版** | `http://localhost:5173` | Vite 开发服务器，**实时编译源码** | 保存文件，浏览器**自动刷新** |

**为什么要有两个？**
开发时用 B，因为改一个字就能立刻看到；做好之后打包成 A，这样只需要启动后端一个服务就能演示。

> 记住这条铁律：**改了前端代码，8080 那个页面不会变。** 必须重新打包。

## 1. 启动开发模式（两个窗口）

### 窗口 1：启动后端

用 ② 册的方式启动（IDEA 点绿三角，或双击 `tools\start-backend.bat`）。

等日志出现 `Started CourseHubApplication`。

**这个窗口不要关。**

### 窗口 2：启动前端

1. 打开命令行（① 册第 0 节的方式 A：在 `D:\桌面\Java项目AIGC\frontend` 文件夹的地址栏敲 `cmd`）
2. 输入：

```
npm run dev
```

3. 等几秒

### 你应该看到

```
  VITE v5.x.x  ready in 832 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.x.x:5173/
  ➜  press h + enter to show help
```

**看到 `Local: http://localhost:5173/` 就成功了。** 这个窗口也别关。

> 第一次跑 `npm run dev` 如果提示 `Cannot find module 'vite'`，
> 说明依赖没装，先在 `frontend` 目录执行 `npm install`（大约 1-3 分钟），再跑 `npm run dev`。

### 打开开发版

浏览器访问 `http://localhost:5173`。

**看起来和 8080 一模一样**，但这次页面是"活的"。

### 它凭什么能调通后端？

Vite 的配置里有一段代理：

```js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true
  }
}
```

意思是：前端发出的 `/api/xxx` 请求，Vite 偷偷转发给 8080 的后端。
浏览器只看到"同源请求"，所以**不会触发跨域报错**。

验证一下：在浏览器打开 `http://localhost:5173/api/courses?page=1&pageSize=1`，
你看到的 JSON 和 `http://localhost:8080/api/courses?...` 完全一样。

## 2. 第一个修改：改首页一行字

### 2.1 目标

把首页大标题「让课程资料 有序、可信、可追溯」改成别的。

改完你会看到：5173 那个页面**自动变了**，而 8080 那个**没变**——这正好验证了两个模式的区别。

### 2.2 打开文件的三种方式（选一种）

#### 方式 A：用记事本（最稳，零风险，推荐第一次用这个）

1. 打开文件资源管理器，进到 `D:\桌面\Java项目AIGC\frontend\src\views`
2. 找到 **`Home.vue`**
3. **右键它** → **`打开方式`** → **`记事本`**
4. 如果右键菜单里没有"打开方式"，就点 **`显示更多选项`** 再找

> 记事本打开 `.vue` 文件会看到一堆代码，没关系，我们只用 `Ctrl + F` 搜一行字。

#### 方式 B：用 IDEA 打开整个 frontend 项目

1. 在 IDEA 里点菜单 **`File`** → **`Open...`**
2. 选择 `D:\桌面\Java项目AIGC\frontend` → `OK`
3. 弹窗问 `Open in New Window` 还是 `This Window` → 选 **`This Window`**
   （选 New Window 会开两个 IDEA 窗口，容易搞混）
4. 左侧项目树现在变成前端的结构了
5. 依次展开 **`src`** → **`views`** → **双击 `Home.vue`**

> ⚠️ 切换项目后，原来后端的项目不在左侧了。
> 想切回去：`File` → `Recent Projects` → 选 `backend`。
> 这也是为什么推荐第一次用记事本 —— 不用来回切。

#### 方式 C：用 IDEA 的"按文件名搜索"（不用切项目）

1. 保持在 backend 项目里
2. 按 **`Ctrl + Shift + N`**（连按三个键）
3. 弹出小搜索框，输入 **`Home.vue`**
4. 列表里会出现 `frontend/src/views/Home.vue` → **双击它**打开
5. 这样可以在 backend 项目里直接编辑前端文件，不用切换

#### 方式 D：用 VS Code（如果装了）

右键 `Home.vue` → 打开方式 → Visual Studio Code。有语法高亮，比记事本舒服。

### 2.3 找到要改的那一行

1. 在打开的文件里按 **`Ctrl + F`**（记事本和 IDEA 都是这个快捷键）
2. 输入：

```
有序、可信、可追溯
```

3. 按**回车**，光标会跳到那一行
4. 你会看到类似这样的代码：

```html
<h1 class="ch-hero-title">
  让课程资料<br />
  <span class="ch-gradient-text">有序、可信、可追溯</span>
</h1>
```

**逐行解释（不用懂也能改）**：

| 这行 | 意思 |
|---|---|
| `<h1 class="ch-hero-title">` | 一个大标题，样式名叫 `ch-hero-title` |
| `让课程资料<br />` | 显示"让课程资料"然后换行（`<br />` 是换行符） |
| `<span class="ch-gradient-text">` | 一个渐变色的文字块开始 |
| `有序、可信、可追溯` | ⭐ **就是这几个字，要改的是它** |
| `</span>` | 渐变文字块结束 |
| `</h1>` | 大标题结束 |

### 2.4 改掉它

1. 用鼠标选中 `有序、可信、可追溯` 这几个字（**只选中文，别选到尖括号**）
2. 直接打字替换成：

```
整理得明明白白
```

3. **按 `Ctrl + S` 保存**
   - 记事本：`文件` → `保存`（或 `Ctrl + S`）
   - 如果弹出"另存为"对话框，说明你可能改了文件名，**取消重来**

### 2.5 你应该看到（两个窗口的对比）

**开发版（`http://localhost:5173`）**：
浏览器**自己刷新了**，标题变成「让课程资料 整理得明明白白」。
你甚至不用按 F5，滚动位置都会保留。

> 这就是"热更新"（HMR）。Vite 检测到文件变了，自动重新编译并刷新页面。

**生产版（`http://localhost:8080`）**：
标题**还是旧的**「有序、可信、可追溯」。

→ **这就是开头那条铁律的现场证明**：改了源码，8080 不会变，必须重新打包。

### 2.6 改回原样

把 `整理得明明白白` 改回 `有序、可信、可追溯`，`Ctrl + S` 保存。
5173 会自动变回来。

### 2.7 改了没生效？四步排查

| 第 1 步 | 确认你改的是 `frontend/src/views/Home.vue`，不是 `dist/` 或 `backend/static/` 里的同名文件 |
|---|---|
| 第 2 步 | 确认**保存了**（记事本标题栏如果还有 `*` 号，说明没保存） |
| 第 3 步 | 确认浏览器看的是 **5173**，不是 8080（看地址栏） |
| 第 4 步 | 看 5173 那个命令行窗口有没有红色报错（语法错了会编译失败） |

> 如果 5173 的命令行窗口刷出红色 `[vite] Internal server error`，
> 说明你把代码改坏了（比如删了个尖括号）。
> 改回来就行 —— **前端改坏了不会影响后端，放心试**。

## 4. 重新打包（让 8080 也变新）

### 方式 A：双击脚本（推荐）

1. 打开 `D:\桌面\Java项目AIGC\frontend`
2. **双击 `build-to-backend.bat`**
3. 等它跑完（约 30-40 秒）

### 脚本干了三件事

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `npm run build` | 把源码编译压缩成 `dist/` 目录 |
| 2 | 删除 `..\backend\src\main\resources\static` | 清掉旧版本 |
| 3 | `xcopy dist → static` | 把新版本塞进后端 |

### 方式 B：手动两条命令

```
cd /d D:\桌面\Java项目AIGC\frontend
npm run build
```

成功会看到：

```
dist/index.html                     0.8 kB
dist/assets/index-COwwRUzV.js      60.55 kB │ gzip:  24.44 kB
dist/assets/vue-C06CYJtW.js       112.11 kB │ gzip:  43.70 kB
dist/assets/elementPlus-xxx.js  1,089.80 kB │ gzip: 342.23 kB
✓ built in 33.41s
```

然后复制：

```
xcopy /e /i /y "D:\桌面\Java项目AIGC\frontend\dist" "D:\桌面\Java项目AIGC\backend\src\main\resources\static"
```

### 方式 C：只改前端的话，还有更快的

如果你只是想临时看看效果，**不重启后端也可以**：

改完 `npm run build` 之后，把 `static` 目录换掉，然后**重启后端**（因为静态资源在启动时被索引，热替换可能不生效）。

> 结论：**改了前端 → 打包 → 重启后端 → 刷新浏览器（`Ctrl + F5` 强刷）**。

## 5. 打包产物长什么样

```
frontend/dist/
├── index.html                 入口，很小（< 1KB）
├── favicon.svg                图标
└── assets/
    ├── index-XXXX.js          你自己的业务代码
    ├── vue-XXXX.js            Vue + Router + Pinia（单独一个包）
    ├── elementPlus-XXXX.js    Element Plus 组件库（最大的一个）
    ├── Home-XXXX.js           首页（路由懒加载，访问才下载）
    ├── CourseDetail-XXXX.js   课程详情
    └── ...                    其余页面各一个
```

**为什么文件名带一串随机字符？**
这叫"内容哈希"。文件内容一变，哈希就变，浏览器就会重新下载；
内容没变，哈希不变，浏览器直接用缓存。这是前端性能优化的标准做法。

**为什么 elementPlus 那个包 1MB 多？**
因为整个 Element Plus 组件库都被打进去了。这是本项目的取舍：
换来"所有组件随取随用"，代价是首屏多下载 342KB（gzip 后）。
真要优化，可以改成按需引入，那是另一个话题。

## 6. 后端改代码后怎么办

后端就简单了：

1. 改 `.java` 文件
2. 点 IDEA 的 **重启按钮**（Run 面板左边的圆形箭头 ↻），或停止再运行
3. 等 `Started CourseHubApplication` 再次出现

**不要**在改完 Java 代码后期望它自动生效 —— 需要重启（除非你装了 JRebel / DevTools）。

> 本项目已经在 `pom.xml` 里加了 `spring-boot-devtools` 的话会自动重启，
> 但改完仍然建议手动确认一次日志。

## 7. 常见坑（详细版见 ⑥ 册）

| 现象 | 原因 | 处理 |
|---|---|---|
| 5173 打不开，命令行报 `EADDRINUSE` | 5173 被上一次的 dev 占了 | 关掉旧窗口，或改 `vite.config.js` 的端口 |
| 改了代码，5173 没反应 | 文件名大小写错 / 编辑的是 dist 里的文件 | 确认编辑的是 `src/` 下的文件 |
| 打包后 8080 还是旧页面 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| `npm run build` 报内存不足 | Node 默认内存上限 | 关掉其他程序重试；或 `set NODE_OPTIONS=--max-old-space-size=4096` |
| 双击 bat 闪退 | GBK 编码损坏 | 用命令行手动执行 `npm run build` |
