## F01 · 双击 bat 一闪就没了

### 现象
双击 `start-redis.bat` / `start-backend.bat` / `build-to-backend.bat`，
黑色窗口闪一下就消失，什么都看不到。

### 原因（本项目踩过三次坑）

1. **bat 文件编码不对**。中文 Windows 的 cmd 默认用 GBK(936) 读文件。
   如果文件是 UTF-8 编码，里面的中文会变成乱码字节，
   cmd 解析器遇到畸形字节会**直接中断执行**。
2. **bat 里出现了 `chcp 65001`**。这是最坑的：
   - GBK 文件 + `chcp 65001` → 乱码 + 闪退
   - UTF-8 文件 + `chcp 65001` → 实测报 `'.' is not recognized as an internal or external command`
   
   **结论：本项目所有 bat 一律 GBK 编码，且绝不出现 `chcp`。**
3. **bat 里用了 `if (...)` 括号块**，中文写在括号里容易触发解析异常。
   本项目改用 `goto` 标签绕开。
4. **`echo` 的内容里出现了 `>` 或 `<`**。
   这是本项目实测踩到的坑：原来有一行写的是
   `echo   启动顺序：MySQL(常驻) -> Redis -> 后端`，
   cmd 把 `-> Redis` 当成了"把输出重定向到名为 Redis 的文件"，
   把 `-> 后端` 当成了重定向到文件"后端"，
   结果**目录里凭空多出两个奇怪的文件，而提示语根本没打印出来**。
   → 修法：echo 里想表达箭头就写"然后"或 `--`，**绝不要写 `->`**。

### 怎么修

**最快的验证方式**：不用双击，用命令行跑，这样错误信息不会被关掉：

1. 在 `D:\桌面\Java项目AIGC\tools` 文件夹地址栏敲 `cmd` 回车
2. 输入：

```
start-redis.bat
```

3. 回车。这样即使出错，窗口也不会立刻关，你能看到报错。

**如果是编码问题**，用记事本另存为：
1. 右键 bat → `打开方式` → `记事本`
2. `文件` → `另存为`
3. 底部「编码」选 **`ANSI`**（就是 GBK）
4. 覆盖保存

**或者干脆绕过 bat**，直接敲命令：

```
cd /d E:\java\redis
redis-server.exe redis.conf
```

## F02 · 端口 8080 被占用

### 现象
后端启动日志里出现：

```
Web server failed to start. Port 8080 was already in use.
```

或者 `APPLICATION FAILED TO START`。

### 原因
已经有一个程序（很可能是你之前没关干净的后端）占着 8080。

### 怎么修

**第 1 步：找出是谁占的**

```
netstat -ano | findstr ":8080" | findstr "LISTENING"
```

输出最后那个数字就是进程号（PID），比如 `17532`。

**第 2 步：看这是什么程序**

```
tasklist | findstr "17532"
```

**第 3 步：杀掉它**

```
taskkill /F /PID 17532
```

把 `17532` 换成你实际的 PID。

**替代方案：换个端口启动**

如果不想杀进程，可以让后端换个端口：

```
cd /d D:\桌面\Java项目AIGC\backend
mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8081"
```

然后浏览器访问 `http://localhost:8081`。

> ⚠️ 换端口后，前端的 `/api` 代理还指向 8080，所以**开发模式（5173）会连不上**。
> 单端口模式（直接访问 8081）没问题。

## F03 · Redis 连不上

### 现象
后端启动日志里出现：

```
Unable to connect to Redis
io.lettuce.core.RedisConnectionException: Unable to connect to localhost:6379
```

或者页面登录时报"系统繁忙"。

### 原因
Redis 没启动，或者启动了又关了。

### 怎么修

**第 1 步：确认**

```
E:\java\redis\redis-cli.exe ping
```

- 返回 `PONG` → Redis 正常，问题不在这
- 返回 `Could not connect to Redis at 127.0.0.1:6379: Connection refused` → 没启动

**第 2 步：启动**

双击 `D:\桌面\Java项目AIGC\tools\start-redis.bat`，
等出现 `Ready to accept connections`。

**第 3 步：重新验证**

```
E:\java\redis\redis-cli.exe ping
```

**第 4 步：重启后端**

Redis 是在后端启动时建立连接的，Redis 恢复后必须重启后端。

> 记忆口诀：**Redis 窗口关掉 = 服务停掉**。
> 那个黑窗口不是"卡住了"，它本来就该停在那里。

## F04 · 数据库密码错误

### 现象
```
java.sql.SQLException: Access denied for user 'root'@'localhost' (using password: YES)
```
或者
```
Access denied for user 'root'@'localhost' (using password: NO)
```

### 原因
`application-local.yml` 里写的密码跟 MySQL 实际密码不一致。
`using password: NO` 说明**根本没读到密码**（文件不存在或字段名写错）。

### 怎么修

**第 1 步：确认文件存在**

看 `D:\桌面\Java项目AIGC\backend\src\main\resources\` 下有没有
`application-local.yml`（不是 `.example`）。

没有就复制一份：
1. 复制 `application-local.yml.example`
2. 重命名为 `application-local.yml`（去掉 `.example`）
3. 用记事本打开填密码

**第 2 步：确认密码正确**

用命令行手动连一次：

```
"E:\java\MySQL\MySQL Server 8.2\bin\mysql.exe" -uroot -p
```

输入你写在 yml 里的那个密码。
连不上 → 密码错了，去 `application-local.yml` 改。

**第 3 步：确认没有别的地方覆盖了密码**

打开 `application-dev.yml`，**搜索 `password:`**。
如果那里有一行 `password:`，**删掉那一行**。

> 原因：`application-dev.yml` 会 `import` 本地配置，
> 但 import 进来的文件**优先级更低**。dev 里一旦写了 password，
> 就会覆盖掉 local 里的真实密码。

**第 4 步：重启后端**

## F05 · 网页全白 / 显示"后端未连接"

### 现象
- 打开 `localhost:8080` 一片白，什么都没有
- 或者首页能开，但状态条显示「后端未连接」+「重新检测」

### 分两种情况

#### 情况 A：页面全白

**第 1 步：打开控制台看报错**

在浏览器按 `F12` → 点 `Console`（控制台）标签。

| 控制台里的报错 | 意思 | 怎么修 |
|---|---|---|
| `Failed to load resource: 404`，路径含 `/assets/` | 前端产物没同步到后端 | 见 F18 |
| `net::ERR_CONNECTION_REFUSED` | 后端没启动 | 启动后端 |
| `Uncaught SyntaxError` | 静态文件损坏 | 重新打包（④ 册第 4 节） |

**第 2 步：直接访问静态文件**

浏览器打开：

```
http://localhost:8080/index.html
```

能开 → 路由问题；打不开 → 静态资源真的没部署。

#### 情况 B："后端未连接"

这说明前端页面在跑，但调 `/api/health` 失败。

**第 1 步：直接访问健康检查**

```
http://localhost:8080/api/health
```

- 返回 JSON → 后端正常，是浏览器的临时问题 → 点「重新检测」
- 打不开 → 后端没启动，回到 ② 册

**第 2 步：如果是 5173 开发模式**

5173 上显示"后端未连接"，通常是：
- 后端没启动（8080 不通）
- `vite.config.js` 里的 proxy 目标被改了

验证：浏览器打开 `http://localhost:5173/api/health`。
返回 JSON 说明代理正常。

### 现象

应该列出 **16 张表**。

## F07 · 编译报"无效的源发行版 11"

### 现象
IDEA 编译或 `mvn compile` 时报：

```
java: 无效的源发行版: 11
```
或
```
Fatal error compiling: invalid target release: 11
```

### 原因
编译时用的 JDK 版本低于 11（通常是 8）。

### 怎么修（三处都要改）

**① IDEA 的 Project SDK**

`File` → `Project Structure` → `Project` →
- SDK：`11`
- Language level：`11`

**② IDEA 的 Modules**

同一个窗口 → 左侧 `Modules` → 选中模块 → `Sources` 标签 →
`Language level` 设为 `11`

**③ IDEA 的编译器**

`File` → `Settings` → `Build, Execution, Deployment` → `Compiler` → `Java Compiler` →
`Project bytecode version` 设为 `11`

**④ Maven 的 JDK**

`File` → `Settings` → `Build, Execution, Deployment` → `Build Tools` → `Maven` →
`JDK for importer` 选 `11`

改完 **重启 IDEA**，再 `Build` → `Rebuild Project`。

## F08 · Maven 依赖下载失败 / 卡住

### 现象
- 底部进度条一直转，"Downloading from central..."
- 或者报 `Could not resolve dependencies`
- 或者 `Connection timed out`

### 原因
默认从国外的 Maven 中央仓库下载，国内网络慢或不稳定。

### 怎么修

**方案 1：换阿里云镜像（推荐，一次性解决）**

1. 找到 Maven 配置文件：`E:\java\apache-maven-3.9.16\conf\settings.xml`
2. 用记事本打开
3. 找到 `<mirrors>` 和 `</mirrors>` 这一段（大概在 140-160 行）
4. 在里面**插入**：

```xml
<mirror>
  <id>aliyunmaven</id>
  <mirrorOf>*</mirrorOf>
  <name>阿里云公共仓库</name>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

5. 保存，回 IDEA 点 Maven 面板的**刷新按钮**（🔄）

**方案 2：先下完再用**

第一次导入项目时耐心等（可能 10 分钟）。下载完会缓存到
`C:\Users\liuwe\.m2\repository`，以后就不再下了。

**方案 3：强制重新下载**

如果某个依赖下了一半坏了：

```
cd /d D:\桌面\Java项目AIGC\backend
mvn -U clean install -DskipTests
```

`-U` 表示强制更新快照。

## F09 · 后端端口莫名其妙变成 49987

### 现象
日志里写：

```
Tomcat started on port(s): 49987 (http)
```

浏览器打开 8080 打不开，49987 才能打开。

### 原因
某些 IDE（尤其是通过 IDE 内置运行配置、或者装了某些插件时）
会往环境变量里注入一个 `SERVER__PORT`。
Spring Boot 的"宽松绑定"会把它当成 `server.port`，覆盖掉配置文件里的 8080。

### 怎么修

**方案 1：清掉环境变量后启动（命令行）**

```bash
unset SERVER__PORT
cd /d D:\桌面\Java项目AIGC\backend
mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8080"
```

**方案 2：IDEA 里检查运行配置**

`Run` → `Edit Configurations...` → 选中 `CourseHubApplication` →
看 `Environment variables` 里有没有 `SERVER__PORT` → 有就删掉。

**方案 3：项目自带的 bat 已经处理了**

`tools\start-backend.bat` 已经显式设置了 `JAVA_HOME` 并直接用 `mvn spring-boot:run`，
不会带上 IDE 注入的变量。

## F10 · IDEA 里代码全红

### 现象
打开 `backend` 后，`import org.springframework...` 全是红色，
提示 `Cannot resolve symbol 'springframework'`。

### 原因
Maven 依赖还没下载完，或者 IDEA 没把 `pom.xml` 当成 Maven 项目。

### 怎么修

**第 1 步：认项目**

左侧 `Project` 面板，右键 `pom.xml` → **`Add as Maven Project`**
（如果菜单里是 `Maven` → `Reload project`，点那个）。

**第 2 步：刷新依赖**

右侧边栏 `Maven` 面板 → 点左上角的**刷新图标**（两个箭头转圈）。

**第 3 步：等**

底部出现 "Resolving dependencies" 进度条，等它消失。
第一次可能 5-10 分钟。

**第 4 步：清缓存重来（最后的办法）**

`File` → `Invalidate Caches...` → 勾选 `Clear file system cache and Local History` →
点 `Invalidate and Restart`。

IDEA 重启后会重新索引，需要几分钟。

## F11 · 登录后所有接口返回 40101

### 现象
登录成功了（提示"登录成功"），但点任何需要登录的功能都失败，
接口返回：

```json
{ "code": 40101, "message": "未登录或登录已过期" }
```

### 原因
1. token 没有正确带上（前端 request.js 的问题）
2. token 过期（本项目设的是 7 天）
3. 后端重启过，但 JWT 密钥变了（如果你改过 `JWT_SECRET` 环境变量）

### 怎么修

**第 1 步：看浏览器存了什么**

按 `F12` → `Application`（应用）标签 → 左侧 `Local Storage` → 
点 `http://localhost:8080`。

应该有 `token` 这一项。没有 → 前端没存进去。

**第 2 步：退出重登**

点右上角昵称 → 退出登录 → 重新登录。

**第 3 步：清浏览器存储**

`F12` → `Application` → 右键 `Local Storage` → `Clear`，
然后 `Ctrl + F5` 强刷，重新登录。

**第 4 步：确认后端密钥没变**

如果你设过 `JWT_SECRET` 环境变量又改过值，所有旧 token 都会失效。
重启后端 + 重新登录即可。

## F12 · 上传资料失败

### 现象
上传进度条走到 100%，然后提示"上传失败，请重试"，
或者后端日志报错。

### 按报错分情况

| 提示 | 原因 | 怎么修 |
|---|---|---|
| `不支持的文件类型` | 扩展名不在白名单 | 只支持 pdf/doc/docx/ppt/pptx/xls/xlsx/jpg/jpeg/png/gif/zip/rar/7z/mp4 |
| `文件大小超出限制` | 超过 500MB | 压缩后再传，或改 `application.yml` 的 `max-file-size` |
| `文件内容与扩展名不匹配` | 改了扩展名的假文件 | 用真实文件（本项目会校验文件头 magic number） |
| `请先登录` | 没登录 | 先登录 |
| `无权在该课程上传` | 不是课程成员 | 先点"加入课程" |
| 进度条卡在某处 | 分片上传中断 | 重新上传即可，已传的分片不会重传（断点续传） |
| `上传失败：Request failed with status code 413` | 请求体太大 | 检查 Nginx/网关限制（本机直连不会有这问题） |

### 排查顺序

1. 看浏览器 `F12` → `Network` → 找到红色的请求 → 看 `Response` 里的 `message`
2. 看后端 IDEA 的 `Run` 面板有没有红色异常
3. 检查 `backend\upload\temp\` 目录有没有残留的分片（有说明传到一半失败了）

## F13 · 下载报 403 / 404

### 现象
点下载，提示"下载失败"，或返回 403/404。

| 状态码 | 含义 | 原因 | 怎么修 |
|---|---|---|---|
| 401 | 未登录 | token 没带 | 重新登录 |
| 403 | 无权限 | 资料的可见性是"仅自己"或"仅本课程"，你不是成员 | 用上传者账号登录，或先加入课程 |
| 404 | 找不到 | **物理文件丢了**（比如你清空了 upload 目录，或换了电脑没带文件） | 重新上传这份资料 |

### 特别说明：换电脑后文件全丢

数据库里记着"文件存在 `2026/10/17/xxx.pdf`"，但新电脑的 `backend\upload` 是空的。
**数据库和文件必须一起搬**：

```
1. 旧电脑：备份数据库（⑤ 册第 5 节）
2. 旧电脑：把 backend\upload 整个文件夹复制走
3. 新电脑：导入数据库 + 把 upload 文件夹放回 backend\ 下
```

## F14 · 刷新页面变 404

### 现象
在 `http://localhost:8080/#/courses` 页面按 `F5`，页面变成 404 或空白。

### 原因
如果你的地址里**没有 `#`**（比如手打成了 `localhost:8080/courses`），
浏览器会真的去请求 `/courses` 这个路径，后端找不到就 404。

### 怎么修

**确认地址带 `#`**：

```
http://localhost:8080/#/courses      ✅ 正确
http://localhost:8080/courses        ❌ 错误
```

本项目用的是 **hash 路由**（`createWebHashHistory`），
`#` 后面的部分浏览器不会发给服务器，所以永远不会 404。

> 如果确实想用不带 `#` 的漂亮地址，需要改成 history 模式 +
> 后端配置 fallback（把未匹配的路径都返回 index.html）。
> 本项目故意不做，因为部署到静态服务器时 hash 模式零配置。

## F15 · 中文显示成乱码

### 现象
- 命令行窗口里中文变成 `����`
- 或者网页上中文变成 `???`
- 或者 bat 里的提示是乱码

### 分情况

| 场景 | 原因 | 怎么修 |
|---|---|---|
| **在 Git Bash / 某些终端里看 bat 输出** | bat 是 GBK，终端按 UTF-8 显示 | 这是**显示问题，不影响功能**。在真正的 cmd 窗口里看是正常的 |
| **网页中文乱码** | 数据库连接字符集错 | 检查 JDBC url 里是 `characterEncoding=UTF-8`（不是 `utf8mb4`） |
| **数据库里存的中文是 `???`** | 库或表不是 utf8mb4 | 重新执行 `init_all.sql`（它建库时指定了 utf8mb4） |
| **控制台日志中文乱码** | IDEA 的编码设置 | `Settings` → `Editor` → `File Encodings` → 全设 `UTF-8` |

> ⚠️ 注意：`characterEncoding=utf8mb4` 是**错误写法**，
> JDBC 只认 `UTF-8`。写错会抛 `Unsupported character encoding 'utf8mb4'`。

## F19 · MySQL 服务启动失败

### 现象
`services.msc` 里点启动，报错：
```
Windows 无法启动 MySQL80 服务（位于 本地计算机 上）。
错误 1067：进程意外终止。
```

### 怎么修

**第 1 步：看错误日志**

打开 `E:\java\MySQL\MySQL Server 8.2\data\`，
找 `.err` 结尾的文件，用记事本打开看最后 30 行。

**常见原因**：

| 日志关键字 | 原因 | 解决 |
|---|---|---|
| `another mysqld process` | 已经有一个 MySQL 在跑 | 先用 `netstat` 确认；如果 3306 已在听，服务其实是好的 |
| `InnoDB: Unable to lock ./ibdata1` | 数据文件被别的进程占用 | 重启电脑 |
| `Can't create/write to file` | 数据目录权限不对 | 右键 `data` 文件夹 → 属性 → 安全 → 给 `NETWORK SERVICE` 完全控制 |
| `Unknown/unsupported storage engine` | 配置文件被改坏 | 检查 `my.ini` 有没有乱码 |

**第 2 步：用命令行启动看详细报错**

管理员命令行：

```
net start MySQL80
```

（如果服务名不是 MySQL80，先执行 `sc query type= service state= all | findstr MySQL`）

## F20 · `/druid` 登录不进去

### 现象
打开 `http://localhost:8080/druid`，弹出登录框，输 `admin/admin` 进不去。

### 原因
Druid 监控页的账号密码来自配置：

```yaml
login-username: admin
login-password: ${DRUID_PASSWORD:admin}
```

`${DRUID_PASSWORD:admin}` 的意思是：优先读环境变量 `DRUID_PASSWORD`，
没有就用默认值 `admin`。

### 怎么修

**如果你设过 `DRUID_PASSWORD` 环境变量**，用那个值登录。
不确定的话，打开命令行：

```
echo %DRUID_PASSWORD%
```

有输出就是它。

**想直接改成固定密码**：改 `application-dev.yml` 里那一行，然后重启。

> 这个账号跟网站登录账号完全无关，不要搞混。

## F21 · 举报处理页提示"需要管理员权限"

### 现象
打开 `/#/admin/reports`，显示：

> 需要管理员权限
> 举报处理页面仅对管理员开放。当前账号没有该权限。

### 原因
你登录的不是管理员账号。

### 怎么修（正常操作）

用 `admin` 账号登录（密码 `Demo123456`）。

### 如果你想让某个学生变成管理员

在数据库里改：

```sql
UPDATE sys_user SET role = 'ADMIN' WHERE username = '2025210101';
```

然后**该用户必须重新登录**（角色写在 JWT 里，旧 token 还是旧角色）。

> 反过来也要注意：把管理员降级成学生后，他手上的旧 token 仍然有管理员权限，
> 直到 token 过期（7 天）。这是 JWT 无状态的固有特点，
> 生产环境要靠"短过期 + 刷新令牌 + 黑名单"来解决。

## F22 · 报时区错误

### 现象
```
java.sql.SQLException: The server time zone value '中国标准时间' is unrecognized
```

### 原因
MySQL 8 需要明确时区，而 JDBC 驱动读到了中文时区名，认不出来。

### 怎么修

本项目的连接串里已经加了 `serverTimezone=Asia/Shanghai`，
所以**用项目自己的配置不会出这个问题**。

如果你是用 IDEA 的 Database 工具连的，在连接设置里加：
- `Advanced` 标签 → `serverTimezone` = `Asia/Shanghai`

或者改 MySQL 全局时区：

```sql
SET GLOBAL time_zone = '+08:00';
```

## F23 · 传大文件失败

### 现象
传 100MB 以上的文件失败，报 413 或超时。

### 本项目的限制

| 限制项 | 值 | 在哪改 |
|---|---|---|
| 单文件最大 | 500MB | `application.yml` 的 `spring.servlet.multipart.max-file-size` |
| 单次请求最大 | 600MB | 同上 `max-request-size` |
| 分片大小 | 5MB | `application.yml` 的 `coursehub.file.chunk-size` |
| 业务层上限 | 500MB | `coursehub.file.max-size` |

### 怎么修

1. 想传更大的文件 → 同时调大上面四个值
2. 如果部署在 Nginx 后面 → 还要改 Nginx 的 `client_max_body_size`
3. 传 500MB 以上建议改用分片上传接口（前端已自动处理，超过 5MB 就走分片）

## F24 · 页面样式全乱了

### 现象
文字变黑、按钮变蓝（Element Plus 默认色）、圆角消失。

### 原因
CSS 导入顺序错了。

`main.js` 里必须是：

```js
import 'element-plus/dist/index.css'   // 先：组件库默认样式
import '@/styles/main.css'             // 后：我们的覆盖样式
```

**顺序反了，覆盖就失效。**

### 怎么修

打开 `frontend/src/main.js`，确认这两行的顺序，
改完 `npm run dev` 或重新打包。

## 附：报错自查通用四步法

遇到任何报错，按这个顺序做：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1 | **看完整报错的第一行** | 第一行通常是根因，后面的都是"因为上面那个错了" |
| 2 | **看 `Caused by:` 那几行** | Java 的异常是一层层包的，真正的根因在最里面的 `Caused by` |
| 3 | **搜关键字**（不是整段报错） | 比如搜 `Port 8080 was already in use`，别搜整段 |
| 4 | **确认"最近改了什么"** | 90% 的问题来自刚刚的改动，先撤销试试 |

### 三个最该看的日志位置

| 位置 | 看什么 |
|---|---|
| IDEA 的 `Run` 面板 | 后端实时日志 |
| 浏览器 `F12` → `Console` | 前端报错 |
| 浏览器 `F12` → `Network` | 请求的 URL、状态码、返回内容 |
