# 第 ⑤ 册 · 数据库与接口

> 目标：能自己打开数据库看数据、改数据；能在网页上直接调后端接口。
> 这两件事是"从使用者变成开发者"的标志。

---

## 第一部分：看数据库

### 1. 三种工具，选一种

| 工具 | 优点 | 缺点 |
|---|---|---|
| **IDEA 自带的 Database 面板** | 不用装新软件，项目里就有 | 第一次配置稍绕 |
| **Navicat** | 界面友好，中文，功能全 | 要另外装（收费，但有免费版 Navicat Premium Lite） |
| **命令行 mysql** | 不装任何东西 | 要记 SQL，看结果不直观 |

**推荐：IDEA 自带的**（你已经有 IDEA 了，零成本）。

### 2. 用 IDEA 连数据库（推荐）

#### 2.1 打开 Database 面板

1. IDEA 右侧边栏找 **`Database`** 字样（如果没有，点最右边的「⋯」或菜单
   `View` → `Tool Windows` → `Database`）
2. 点面板左上角的 **`+`** → `Data Source` → **`MySQL`**

#### 2.2 填连接信息

弹出配置窗口，按下表填：

| 字段 | 填什么 |
|---|---|
| Name | `CourseHub Local`（随便取） |
| Host | `localhost` |
| Port | `3306` |
| User | `root` |
| Password | 你的 MySQL 密码（就是 `application-local.yml` 里那个） |
| Database | `coursehub` |

#### 2.3 补一个关键设置（不填会报时区错误）

点窗口下方的 **`Advanced`** 标签 → 找到 `serverTimezone` → 值填 `Asia/Shanghai`。

（或者点 `Test Connection` 报 `The server time zone value ... is unrecognized` 时，
回来做这一步。）

#### 2.4 测试并保存

1. 点 **`Test Connection`** → 出现绿色的 **`Succeeded`** / 「已成功」
2. 点 **`OK`**

#### 2.5 如果提示缺驱动

第一次连 MySQL，IDEA 会提示 `Download missing driver files` →
点那个蓝色的下载链接，等它下完（约 5MB）→ 再点 `Test Connection`。

#### 2.6 看数据

左侧展开：

```
CourseHub Local
 └ coursehub
    └ public（或直接列出 16 张表）
       ├ sys_user
       ├ course
       ├ resource
       └ ...
```

**双击任意一张表** → 右侧打开数据视图，能看到真实的行。

**双击 `sys_user` 表看看**：4 行，密码字段是一串 `$2a$10$...` 的乱码 —— 
那是 BCrypt 哈希，**不可逆**，所以数据库被拖走也拿不到明文密码。

### 3. 16 张表都是干什么的

| 表名 | 存什么 | 关键字段 |
|---|---|---|
| `sys_college` | 学院字典 | name, code |
| `sys_user` | 用户 | username, password(BCrypt), role, credit_score |
| `course` | 课程 | course_code, name, teacher, term, owner_id |
| `course_member` | 课程成员关系 | course_id, user_id, role(OWNER/STUDENT) |
| `chapter` | 课程章节 | course_id, name, sort_order |
| `file` | **物理文件**登记 | storage_path, size, md5, ref_count |
| `resource` | 资料的**元信息** | course_id, file_id, title, visibility, score |
| `resource_version` | 版本树 | resource_id, version_no, file_id |
| `comment` | 评论（两级） | resource_id, user_id, parent_id, root_id |
| `collection` | 收藏 | user_id, resource_id |
| `download_record` | 下载记录 | user_id, resource_id, ip |
| `report` | 举报 | target_type, target_id, reason, status |
| `tag` | 标签 | name, usage_count |
| `resource_tag` | 资料-标签关联 | resource_id, tag_id |
| `notification` | 站内通知 | user_id, type, title, is_read |
| `audit_log` | 审计日志 | user_id, action, method, params, ip |

#### 三个必须理解的关系

**① 为什么 `file` 和 `resource` 要分开？**

- `file` = 磁盘上的那个物理文件（一个文件一行，有 MD5、大小、存放路径）
- `resource` = 一条"资料"（标题、描述、所属课程、可见性）

因为**同一个文件可以被多条资料引用**（秒传就是靠这个）。
`file.ref_count` 记录被引用几次，删资料时减 1，减到 0 才真删物理文件。

**② `resource_version` 是版本树**

一条资料有多个版本，每个版本指向一个 `file`。
这样"上传新版本"不用改 `resource` 表，只加一行版本记录。

**③ 软删除 `is_deleted`**

核心表都有这个字段。删数据不是 `DELETE`，而是 `UPDATE is_deleted = 1`。
好处：数据可恢复，审计可追溯。所有查询都带 `WHERE is_deleted = 0`。

### 4. 六个实用 SQL（复制粘贴就能跑）

在 IDEA 的 Database 面板点 **`Jump to Query Console`**（或右键库名 → `New` → `Query Console`），
粘贴 SQL，按 `Ctrl + Enter`（或点绿色三角）执行。

#### ① 看所有用户和角色

```sql
SELECT id, username, nickname, role, credit_score, level, created_at
FROM sys_user
WHERE is_deleted = 0
ORDER BY id;
```

#### ② 看资料 + 上传者 + 课程（三表关联）

```sql
SELECT r.id,
       r.title,
       r.score,
       r.download_count,
       c.name  AS course_name,
       u.nickname AS uploader
FROM resource r
LEFT JOIN course c   ON c.id = r.course_id
LEFT JOIN sys_user u ON u.id = r.uploader_id
WHERE r.is_deleted = 0
ORDER BY r.id;
```

#### ③ 看某份资料的版本历史

```sql
SELECT v.version_no, v.change_note, f.original_name, f.size, v.created_at
FROM resource_version v
LEFT JOIN file f ON f.id = v.file_id
WHERE v.resource_id = 1
ORDER BY v.version_no;
```

#### ④ 看物理文件有没有被正确引用（引用计数是否一致）

```sql
SELECT f.id, f.original_name, f.size, f.ref_count,
       (SELECT COUNT(*) FROM resource r WHERE r.file_id = f.id AND r.is_deleted = 0) AS real_ref
FROM file f
HAVING f.ref_count <> real_ref;      -- 有输出说明计数对不上，需要排查
```

#### ⑤ 看审计日志（谁在什么时候干了什么）

```sql
SELECT id, user_id, action, method, uri, ip, cost_ms, created_at
FROM audit_log
ORDER BY id DESC
LIMIT 20;
```

#### ⑥ 手动改一条数据试试（改完记得改回来）

```sql
UPDATE resource SET title = '我改过的标题' WHERE id = 1;
```

回到网站刷新资料库 → 标题变了。
**再执行一次改回去**：

```sql
UPDATE resource SET title = '南京信息工程大学2026年学生创新创业竞赛目录' WHERE id = 1;
```

> 这正是"后端只是数据库的一层包装"的直观体现。
> 你绕过页面直接改库，页面立刻反映 —— 说明数据是**真的存在数据库里**。

### 5. 备份与恢复（重要，养成习惯）

#### 备份（导出）

打开命令行，执行：

```
"D:\桌面\Java项目AIGC\tools\backup-db.bat"
```

或者手动（推荐放 F 盘，别放 C 盘）：

```
"E:\java\MySQL\MySQL Server 8.2\bin\mysqldump.exe" -uroot -p --default-character-set=utf8mb4 --single-transaction coursehub > "F:\coursehub_backup_20261017.sql"
```

输入密码后，F 盘会多一个 `.sql` 文件（本项目约 100KB）。

#### 恢复（导入）

```
"E:\java\MySQL\MySQL Server 8.2\bin\mysql.exe" -uroot -p coursehub < "F:\coursehub_backup_20261017.sql"
```

#### 什么时候要备份

- 改动数据库结构之前
- 批量执行 SQL 之前
- 想在实验环境里瞎折腾之前

### 8. 在网页上真调一次接口（重点）

#### 8.1 先拿 token

1. 在 `doc.html` 左侧找到 **「认证管理」** → **`POST /api/auth/login`**
2. 点开，点右侧 **`调试`** 标签
3. 在请求体（Body）里填：

```json
{
  "username": "admin",
  "password": "Demo123456"
}
```

4. 点 **`发送`**
5. 响应区会返回：

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEsInVzZXJuYW1lIjoiYWRtaW4i...",
    "user": { "id": 1, "username": "admin", "nickname": "系统管理员", "role": "ADMIN" }
  }
}
```

6. **把 `token` 的值整串复制下来**（很长，别漏字符）

#### 8.2 把 token 配置进去（一次配置，全局生效）

1. 点 doc.html 右上角或左侧的 **「Authorize」/「全局参数设置」**
2. 如果它要你填 Header：
   - 参数名：`Authorization`
   - 参数值：`Bearer ` + 你复制的 token（**注意 Bearer 后面有一个空格**）
3. 确认

#### 8.3 调一个需要登录的接口

左侧找 **「资料管理」** → `GET /api/resources/{id}` →
调试 → `id` 填 `1` → **`发送`**。

返回里能看到资料的完整信息，包括 `uploaderName`、`versions` 等。

#### 8.4 调管理接口

**「管理端」** → `POST /api/admin/recalc-score` → 发送。

返回：

```json
{ "code": 0, "message": "重算完成", "data": 3 }
```

`data: 3` 表示重算了 3 条资料的评分。

> 用普通学生 token 调这个接口，会返回 `code: 40302`「权限不足」。
> 这就是 `@RequireRole("ADMIN")` 在起作用。

### 9. 用命令行调接口（不打开网页也行）

```bash
# 1. 登录拿 token（把返回的 token 复制下来）
curl -s -X POST http://localhost:8080/api/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"Demo123456\"}"

# 2. 带 token 查自己的信息
curl -s http://localhost:8080/api/auth/me ^
  -H "Authorization: Bearer 这里粘贴token"
```

> Windows 命令行里换行用 `^`，在 Git Bash 里用 `\`。

### 10. Druid 监控（看 SQL 跑得快不快）

浏览器打开：

```
http://localhost:8080/druid
```

登录：用户名 `admin`，密码 `admin`（这是监控页自己的账号，跟网站账号无关）。

你能看到：

| 页面 | 看什么 |
|---|---|
| 数据源 | 连接池有几个连接、多少空闲 |
| **SQL 监控** | 每条 SQL 执行了几次、平均耗时多少毫秒 |
| SQL 防火墙 | 被拦下的可疑 SQL（防注入） |
| URI 监控 | 每个接口被调了几次、最慢多少毫秒 |

**实用场景**：你觉得某个页面加载慢 → 点几个页面 → 回头来 SQL 监控按"执行时间"排序 →
就能定位是哪条 SQL 慢。

> 本项目配了 `slowSqlMillis=1000`，超过 1 秒的 SQL 会被单独记录。
