# 第 ⓿ 册 · 先认识这些文件（.bat / .yml / .md 到底是什么）

> 这一册不讲项目，只讲**文件**。
> 因为后面每一册都会说"打开 `application-local.yml`""双击 `start-redis.bat`"，
> 如果你连这些后缀是什么都不知道，那些步骤就没法执行。
>
> 看完这一册，你至少能做到三件事：
> ① 看到任何文件都能判断「这是什么、该用什么打开、能不能改」
> ② 知道哪些文件双击就干活、哪些双击会出事
> ③ 能在自己电脑上把"隐藏的文件后缀"显示出来

## 一、文件后缀是什么

### 一句话

**文件后缀 = 文件名最后那个点后面的几个字母，它告诉电脑"我是什么类型的文件"。**

```
start-redis.bat
└─────┬────┘└┬┘
    文件名   后缀 → 电脑看到 .bat 就知道"这是批处理脚本，用 cmd 打开执行"
```

### 一个类比

想象你收到一堆快递：

| 快递 | 相当于 |
|---|---|
| 写着"易碎"的箱子 | `.pdf`、`.pptx` —— 要用专门的软件小心打开 |
| 写着"即食"的袋子 | `.bat`、`.exe` —— 拆开就能吃（双击就运行） |
| 写着"原料"的麻袋 | `.java`、`.vue` —— 不能直接吃，得先加工（编译/打包）才算成品 |

电脑就是那个快递员。它**不看内容，只看标签**。
标签写着 `.bat`，它就丢给 cmd 去执行；写着 `.pdf`，它就丢给 PDF 阅读器。

### 所以后缀决定了三件事

| 决定 | 举例 |
|---|---|
| **用哪个程序打开** | `.md` → 记事本 / Typora；`.sql` → Navicat / IDEA |
| **电脑怎么处理它** | `.bat` 会被**执行**；`.txt` 只会被**显示** |
| **能不能被工具识别** | `.java` 会被 Maven 编译；改名叫 `.txt` 就没人理它了 |

> ⚠️ **最重要的一条警告**：
> **后缀不能乱改。** 把 `a.pdf` 改名成 `a.txt`，不会让 PDF 变成文本，
> 只会让电脑找不到打开它的程序，双击报错。把 `a.jpg` 改成 `a.exe`，
> 也不会让它变成程序。**后缀是"身份标签"，不是"内容转换器"。**

## 二、第一步：先让你电脑把后缀显示出来

Windows **默认隐藏**已知类型的后缀，这是新手最大的坑：
你以为文件叫 `readme`，其实它是 `readme.txt`；
你以为叫 `application-local`，其实它是 `application-local.yml.example`。

### 怎么看

**Windows 11**：打开任意文件夹 → 顶部点 **「查看」** → **「显示」** → 勾选 **「文件扩展名」**

**Windows 10**：打开任意文件夹 → 顶部点 **「查看」** 标签 → 勾选 **「文件扩展名」**

> 勾上之后，所有文件都会露出真名。**这一步必须做**，
> 否则你会在"为什么我改了文件名却不起作用"上浪费一整天。

### 做完之后你会看到的变化

| 之前看到 | 之后看到 |
|---|---|
| `README` | `README.md` |
| `application-local` | `application-local.yml` |
| `start-redis` | `start-redis.bat` |
| `pom` | `pom.xml` |

## 三、三大类文件：先判断"能不能双击"

这是本册最有用的一个分类。**遇到任何陌生文件，先问自己：它属于哪一类？**

### A 类：双击就干活的（可执行）

| 后缀 | 是什么 | 双击会怎样 |
|---|---|---|
| `.bat` | Windows 批处理脚本（一串 cmd 命令写在文本里） | **立刻执行里面的命令**，弹出黑窗口 |
| `.exe` | Windows 程序 | 立刻运行程序 |
| `.sh` | Linux/Mac 的 shell 脚本（本项目有，但 Windows 上双击没用） | Windows 一般会问"用什么打开"，别双击 |
| `.jar` | Java 打包好的程序（一堆 .class 压缩在一起） | 有 Java 环境时会运行（本项目不用双击 jar） |

> ⚠️ **A 类文件不要乱双击**。你不知道里面写了什么，双击就等于"让它随便动你的电脑"。
> 本项目 `tools\` 下的 4 个 `.bat` 是自己写的、安全的，可以放心双击。

### B 类：用软件打开看的（数据 / 文档）

| 后缀 | 是什么 | 用什么打开 | 能改吗 |
|---|---|---|---|
| `.md` | Markdown 文档（就是你现在看的这种） | 记事本 / VS Code / Typora | ✅ 随便改 |
| `.txt` | 纯文本 | 记事本 | ✅ |
| `.yml` | 配置文件（YAML 格式，靠缩进表达层级） | 记事本 / VS Code / IDEA | ⚠️ 能改，但**缩进错一个空格就崩** |
| `.xml` | 配置文件（尖括号标签格式，MyBatis 的 SQL 就写在这里） | IDEA / 记事本 | ⚠️ 标签必须成对 |
| `.json` | 数据交换格式（键值对） | VS Code / 浏览器 / 记事本 | ⚠️ 少个逗号就解析失败 |
| `.sql` | 数据库脚本（建表、插数据的语句） | Navicat / IDEA Database / 命令行 | ⚠️ 执行会真的改数据库 |
| `.log` | 日志文件（程序自己写的运行记录） | 记事本 / VS Code | ❌ 别手改，程序会覆盖 |
| `.conf` | 配置文件（Nginx 用） | 记事本 | ⚠️ |
| `.pdf` | 电子文档 | 浏览器 / PDF 阅读器 | ❌ 一般不改 |
| `.pptx` / `.docx` / `.xlsx` | PPT / Word / Excel | Office / WPS | ✅ |
| `.svg` | 矢量图标（本质是文本） | 浏览器 / 图片查看器 | ✅ |

### C 类：要"加工"才能用的（源代码）

| 后缀 | 是什么 | 谁来处理它 | 双击会怎样 |
|---|---|---|---|
| `.java` | Java 源代码 | Maven 编译成 `.class`，再被 JVM 执行 | 记事本打开（如果装了 IDEA 会用 IDEA 打开） |
| `.vue` | Vue 组件（前端一个页面的 html+js+css 三合一） | Vite 打包成 `.js` | 记事本打开（内容是代码，看着乱） |
| `.js` | JavaScript 代码 | 浏览器直接执行 / Vite 打包 | 记事本打开 |
| `.css` | 样式表（颜色、间距、字体） | 浏览器读取 | 记事本打开 |
| `.html` | 网页骨架 | 浏览器 | **会用浏览器打开**（这是唯一双击有意义的 C 类） |
| `.py` | Python 脚本 | Python 解释器执行 | 可能直接运行（如果装了 Python） |
| `.class` | Java 编译后的字节码 | JVM | ❌ **别动**，二进制，打开是乱码 |

> **核心区别**：A 类是"电脑直接照做"，C 类是"电脑要先翻译一遍才懂"。
> 这就是为什么 `.bat` 双击能用，而 `.java` 双击只能看到一堆字。

## 五、四个最容易搞混的后缀

### ① `.yml` 和 `.yaml`

**同一个东西**，只是后缀长短不同。YAML 的官方推荐是 `.yaml`，
但 Spring Boot 圈子习惯用 `.yml`。本项目全用 `.yml`。

### ② `.md` 和 `.txt`

都是纯文本，但 `.md` 是 **Markdown**：用几个符号就能表示格式。

```markdown
# 一个井号是标题
**两个星号是加粗**

| 竖线 | 是表格 |
|---|---|
```

用记事本打开能看懂（就是多了些符号），用 Typora / VS Code 打开就是排好版的文档。
**GitHub 上的 README 就是 `.md`，会自动渲染成网页。**

### ③ `.xml` 和 `.html`

长得像（都是尖括号），但用途完全不同：

| | `.html` | `.xml` |
|---|---|---|
| 给谁看 | **浏览器**（渲染成页面） | **程序**（读取配置/数据） |
| 本项目里 | 前端页面骨架 | MyBatis 的 SQL、Maven 的 pom |

### ④ `.js` 和 `.java`

名字像，**毫无关系**：

| | `.js` | `.java` |
|---|---|---|
| 全名 | JavaScript | Java |
| 跑在哪 | 浏览器 / Node.js | JVM（Java 虚拟机） |
| 本项目角色 | 前端 | 后端 |

> 这俩就像"雷锋"和"雷峰塔"——名字像，不是一回事。

## 六、怎么打开这些文件（4 种方式，从简到好）

### 方式 1：记事本（最万能，零安装）

**右键文件 → 打开方式 → 记事本**

优点：任何文本文件都能开，永远不会出错。
缺点：没有语法高亮、没有缩进辅助、`.yml` 缩进错了也看不出来。

**适合**：临时看一眼、改一行文字。

### 方式 2：VS Code（推荐装一个）

免费、轻量、能高亮几乎所有语言。
装完右键 → 打开方式 → Visual Studio Code。

**适合**：改配置、看代码、写 Markdown。

### 方式 3：IDEA（你已经有）

打开 `backend` 或 `frontend` 文件夹后，左侧树里双击任意文件即可。
IDEA 会：
- `.java` 编译检查、跳转定义
- `.yml` 缩进对齐提示
- `.xml` 标签自动补全
- `.vue` 高亮

**适合**：改代码（这是主战场）。

### 方式 4：专用工具

| 文件 | 该用什么 |
|---|---|
| `.sql` | Navicat / IDEA 的 Database 面板 / 命令行 mysql |
| `.html` | 浏览器（双击就行） |
| `.pdf` | 浏览器也可以直接拖进去 |
| `.pptx` | WPS / Office |
| `.log` | 记事本 / VS Code（文件大时用 VS Code，记事本会卡） |

### 关于"双击没反应"或"打开方式不对"

Windows 记住的是"上一次用什么打开的"。如果关联错了：

**右键 → 打开方式 → 选择其他应用 → 勾选"始终使用此应用打开"**

## 七、"改了会怎样" 风险表

这是新手最容易出事的地方。改文件之前先查这张表。

| 文件类型 | 改了之后要做什么 | 风险 |
|---|---|---|
| `.md` `.txt` | 什么都不用做 | 无风险 |
| `.yml` | **重启后端**才生效 | 缩进错一个空格 → 启动失败 |
| `.xml`（MyBatis） | 重启后端 | 标签不闭合 → 启动失败 |
| `.java` | **重启后端**（IDEA 里点重启） | 语法错 → 编译失败 |
| `.vue` `.js` `.css` | 开发模式自动刷新；**生产模式要重新打包** | 语法错 → 页面白屏 |
| `.sql` | 执行了就立即生效 | **没有撤销键**，改错要手动改回来 |
| `.class` `.jar` | —— | ❌ **别碰**，改了也没用 |
| `.log` | —— | ❌ 别改，程序会追加覆盖 |
| **任何文件的后缀** | —— | ❌ **绝对不要改名后缀** |

### 三个必须遵守的习惯

1. **改配置前先备份**：复制一份，改名 `xxx.yml.bak`。
   出事了把 `.bak` 去掉后缀换回来。
2. **改 yml 只动值，不动缩进**：
   ```yaml
   spring:
     datasource:
       password: 你的密码     ← 只改这一行冒号后面的内容
   ```
   前面的空格一个都不能动。
3. **改完就看日志**：IDEA 底部 `Run` 面板，有没有红色报错。

## 九、一个反直觉但很重要的点

### 文件后缀 ≠ 文件内容

有人会想："我把 `.txt` 改成 `.java`，是不是就变成 Java 代码了？"

**不是。** 后缀只是标签。

但反过来有个真实情况值得知道：
**有些文件内容对了，只是后缀不对，程序就不认。**

比如 `application-local.yml` 写成 `application-local.yaml` —— Spring Boot 也认（都支持）。
但如果你不小心写成 `application-local.yml.txt`（Windows 隐藏后缀时特别容易发生），
Spring Boot 就**完全看不见这个文件**，然后报"数据库密码为空"。

> 这就是为什么第二册要你先打开"显示文件扩展名"。
> 90% 的"我明明配了却不生效"，都是文件名后缀被偷偷加了 `.txt`。
