## 0. 先学会"打开命令行"

后面的检查命令都要在命令行里敲。Windows 上有三种方式，任选一种，**推荐方式 A**：

### 方式 A：在文件夹里直接开（最不容易出错）

1. 打开文件资源管理器，进到任意文件夹（比如 `D:\桌面\Java项目AIGC`）
2. 点一下**顶部的地址栏**（就是显示路径的那一条）
3. 把里面的内容删掉，敲三个字母 `cmd`
4. 按**回车**

→ 会弹出一个黑色窗口，路径已经定位到当前文件夹。这就是命令行。

### 方式 B：开始菜单

1. 按键盘 `Win` 键（左下角 Windows 图标）
2. 直接敲 `cmd`
3. 回车

→ 弹出黑窗口，默认在 `C:\Users\liuwe`。

### 方式 C：Win + R

1. 同时按 `Win` + `R`
2. 输入 `cmd`
3. 回车

> 三种方式效果一样。**方式 A 的好处**：不用自己 `cd` 切目录，少一个出错点。

### 命令行里的两个基本常识

| 常识 | 说明 |
|---|---|
| 复制粘贴 | 在黑窗口里**不能用 Ctrl+V**。要右键 → 粘贴；或直接点鼠标右键 |
| 怎么停 | 按 `Ctrl + C` 可以中断正在跑的程序；点右上角 × 直接关 |

## 1. 检查 JDK 11（Java 运行环境）

### 为什么需要

后端是 Java 写的，没有 JDK 就跑不起来。**这个项目必须用 JDK 11**，
用 17 或 26 会因为框架版本对不上而报错。

### 怎么做

打开命令行，输入（注意 `-version` 前面是**一个短横**，不是两个）：

```
java -version
```

### 你应该看到

```
java version "11.0.5" 2019-10-15 LTS
Java(TM) SE Runtime Environment 18.9 (build 11.0.5+10-LTS)
Java HotSpot(TM) 64-Bit Server VM 18.9 (build 11.0.5+10-LTS, mixed mode)
```

**判断标准：第一行必须是 `11.x.x`。** 只要不是 11 开头，就是错的。

再检查一下环境变量（决定 Maven 用哪个 JDK）：

```
echo %JAVA_HOME%
```

### 你应该看到

```
E:\java\jdk11
```

### 如果不对怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示 `'java' 不是内部或外部命令` | PATH 里没有 JDK | 见下方"修复脚本" |
| 显示 `17.x` 或 `26.x` | JAVA_HOME 指向了别的 JDK | 见下方"修复脚本" |
| `%JAVA_HOME%` 输出为空 | 环境变量没设 | 见下方"修复脚本" |

### 修复脚本（本机专用，一键搞定）

1. 打开 `D:\桌面\Java项目AIGC\tools\fix-java-path`
2. **右键** `run-fix.bat` → **以管理员身份运行**
3. 看到"修复完成"后，**关掉所有命令行窗口，重新开一个**
4. 重新执行 `java -version` 确认

> 这个脚本会自动清掉 Windows 自带的 `javapath` 干扰项（那个东西会偷偷把
> JAVA_HOME 覆盖成 17），把 `JAVA_HOME` 指向 `E:\java\jdk11`，
> 并把 `E:\java\jdk11\bin` 放到 PATH 最前面。
> 脚本运行前会自动备份原来的 PATH 到同目录的 `PATH_backup_*.txt`。

### 手工修（脚本出问题时用）

1. `Win + R` → 输入 `sysdm.cpl` → 回车
2. 切到「高级」标签 → 点右下「环境变量」
3. 在「系统变量」里：
   - 找 `JAVA_HOME`，双击，值改为 `E:\java\jdk11`
   - 找 `Path`，双击，**删掉**含 `javapath` 的那一条，
     然后「新建」一条 `E:\java\jdk11\bin`
4. 一路「确定」，关掉所有黑窗口重开

## 2. 检查 Maven（Java 的"包管理器"）

### 为什么需要

后端依赖了几十个第三方库（Spring Boot、MyBatis、Redis 客户端…），
Maven 负责把它们下载下来并编译打包。没有它，IDEA 里的代码全是红色报错。

### 怎么做

```
mvn -v
```

### 你应该看到

```
Apache Maven 3.9.16 (2bdd9fddda4b155ebf8000e807eb73fd829a51d5)
Maven home: E:\java\apache-maven-3.9.16
Java version: 11.0.5, vendor: Oracle Corporation, runtime: E:\java\jdk11
Default locale: zh_CN, platform encoding: GBK
OS name: "windows 10", version: "10.0", arch: "amd64", family: "windows"
```

**三个关键点**：
1. Maven 版本 ≥ 3.6
2. `Java version` 必须是 **11**
3. `Maven home` 指向 `E:\java\apache-maven-3.9.16`

### 如果不对怎么办

- 提示 `'mvn' 不是内部或外部命令` → Maven 没进 PATH。
  手工加：环境变量 Path 里新增 `E:\java\apache-maven-3.9.16\bin`，重开命令行。
- `Java version` 显示 17 → 先修第 1 节的 JAVA_HOME，Maven 认的是 JAVA_HOME。

## 3. 检查 MySQL（数据库）

### 为什么需要

用户、课程、资料、评论全都存在 MySQL 里。它是个**开机自启的 Windows 服务**，
平时不用管，但要会判断"它是不是停掉了"。

### 3.1 先看它有没有在跑

```
netstat -ano | findstr ":3306" | findstr "LISTENING"
```

### 你应该看到（至少一行）

```
  TCP    0.0.0.0:3306           0.0.0.0:0              LISTENING       7444
```

最后那个数字（7444）是进程号，每次开机可能不同，不用管。

**如果什么都没输出** → MySQL 没启动，进 3.2。

### 3.2 启动 MySQL

**方式 A：服务管理器（推荐）**

1. `Win + R` → 输入 `services.msc` → 回车
2. 在列表里找名字含 `MySQL` 的项（本机是 `MySQL80` 或 `MySQL82`）
3. 右键 → 「启动」
4. 等状态变成「正在运行」

**方式 B：命令行（管理员）**

1. 开始菜单搜 `cmd` → 右键 → 「以管理员身份运行」
2. 输入：
```
net start MySQL80
```
（服务名不确定就先执行 `sc query type= service state= all | findstr MySQL` 查）

### 3.3 试着连一下

```
mysql -uroot -p
```

然后**直接回车或输入你的密码**（输入时屏幕不显示字符，这是正常的安全设计），
看到下面这样的欢迎信息就成功了：

```
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 12
Server version: 8.2.0 MySQL Community Server - GPL
```

输入 `exit` 回车退出。

> 如果提示 `'mysql' 不是内部或外部命令`，说明 MySQL 的 bin 没进 PATH。
> 用完整路径连：
> ```
> "E:\java\MySQL\MySQL Server 8.2\bin\mysql.exe" -uroot -p
> ```

### 3.4 记住你的 MySQL 密码

后面 ② 册要把它填到一个配置文件里。
**本机已经配好了**（写在 `backend\src\main\resources\application-local.yml`），
你只需要知道"这个文件里有密码"这件事，别把它上传到 GitHub（`.gitignore` 已经排除了）。

## 4. 检查 Redis（缓存）

### 为什么需要

Redis 干两件事：
1. 缓存登录状态、热门搜索词，让接口更快
2. **记录分片上传的进度** —— 传一半断网了，下次能接着传

### 4.1 一键启动（推荐）

打开 `D:\桌面\Java项目AIGC\tools`，**双击 `start-redis.bat`**。

### 你应该看到

一个黑色窗口，先打印一段说明，然后刷出一堆日志，最后停在类似这样：

```
                _._
           _.-``__ ''-._
      _.-``    `.  `_.  ''-._           Redis 8.x
  .-`` .-```.  ```\/    _.,_ ''-._
 (    '      ,       .-`  | `,    )     Running in standalone mode
 |`-._`-...-` __...-.``-._|'` _.-'|     Port: 6379
 ...
[12345] 17 Oct 21:30:12 * Ready to accept connections
```

**判断标准：出现 `Ready to accept connections` 就是成功。**

> ⚠️ **窗口不能关！**
> Redis 是"前台服务"——窗口在，服务在；窗口关，服务停。
> 这就是为什么你会看到它"卡住不动"：它本来就不该动。
> 你可以把这个窗口最小化，但不要点 ×。

### 4.2 验证它真的活着

**再开一个**命令行窗口（原来的别关），执行：

```
E:\java\redis\redis-cli.exe ping
```

应该返回：

```
PONG
```

### 4.3 如果失败怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击后窗口一闪就没了 | bat 编码坏了 | 直接用命令行：`cd /d E:\java\redis` 然后 `redis-server.exe redis.conf` |
| 窗口里全是乱码，然后退出 | 同上 | 同上 |
| 提示 `Could not connect to Redis` | Redis 没启动 | 回到 4.1 |
| 提示端口被占用 | 已经有一个 Redis 在跑 | 不用管，先用 `redis-cli ping` 看是不是已经 PONG 了 |

### 4.4 关于 redis.conf 的两个坑（本机已修复，了解即可）

1. 配置里的 `logfile` 必须是 `logfile ""`（空字符串）。
   如果写成 Windows 路径，Cygwin 版 Redis 会**启动时无任何输出、看起来卡死**。
2. Redis 目录下的 `.bat` 必须是 **GBK 编码且绝不能出现 `chcp` 命令**。
   GBK 文件 + `chcp 65001` 会乱码 + 闪退。

## 6. 检查 IDEA（写代码的工具）

### 为什么需要

IDEA 是启动后端最方便的工具：点一个绿色三角就能跑，报错直接标红。

### 6.1 确认版本

打开 IDEA → 菜单 `Help` → `About`。
社区版（Community）和专业版（Ultimate）都能用，本项目不需要付费功能。

### 6.2 设置 JDK 11（第一次打开项目后必做）

1. 菜单 `File` → `Project Structure...`（快捷键 `Ctrl + Alt + Shift + S`）
2. 左侧选 `Project`
3. `SDK` 下拉框 → 如果列表里没有 11，点 `Add SDK` → `JDK...` →
   选择文件夹 `E:\java\jdk11` → 确定
4. `Language level` 选 `11 - Local variable syntax for lambda parameters`
5. 点 `Apply` → `OK`

### 6.3 检查 Maven 设置

1. `File` → `Settings...`（`Ctrl + Alt + S`）
2. 左侧 `Build, Execution, Deployment` → `Build Tools` → `Maven`
3. `Maven home path` 应该是 `E:\java\apache-maven-3.9.16`
4. `JDK for importer` 选 11
5. `Apply` → `OK`

## 7. 唯一需要你检查的配置文件

### 文件在哪

```
D:\桌面\Java项目AIGC\backend\src\main\resources\application-local.yml
```

### 它是干什么的

存放**数据库密码**这种不能公开的信息。
这个文件已经被 `.gitignore` 排除，**不会上传到 GitHub**，所以可以放心写密码。

### 本机现状：已经配好了

你这台电脑上这个文件已经存在并且填好了密码，**不需要改**。

### 如果换了电脑 / 文件丢了怎么办

1. 在 `backend\src\main\resources\` 下找到 `application-local.yml.example`
2. 复制一份，重命名为 `application-local.yml`（去掉 `.example`）
3. 用记事本打开，把占位符改成你自己的 MySQL 密码：

```yaml
spring:
  datasource:
    password: 你的MySQL密码
```

> ⚠️ 注意：`application-dev.yml` 里**故意没写 password 字段**。
> 如果你在那里加了一行 `password:`，它会覆盖这里的值，导致连不上数据库。
> 这是设计好的，别去动它。

## 8. 数据库初始化（只在"第一次"或"想推倒重来"时做）

### 先判断：需要初始化吗？

**最简单的判断方式**：直接跳到 ② 册启动后端，
看日志里有没有出现 `Table 'coursehub.sys_user' doesn't exist`。

- 出现 → 库还没建，回来做这一节
- 没出现、能正常打开网页 → 库已经建好了，**这一节跳过**

### 一键初始化（推荐）

**方式 A：用 Navicat / DBeaver 等图形工具**

1. 连上本机 MySQL（主机 `localhost`，端口 `3306`，用户 `root`）
2. 打开文件 `D:\桌面\Java项目AIGC\backend\sql\init_all.sql`
3. 点「运行」/「执行」
4. 等它跑完，左侧刷新，能看到 `coursehub` 库和 16 张表

**方式 B：用命令行（不需要装任何工具）**

1. 打开命令行
2. 执行（一行，注意最后的 `<` 是"导入"的意思）：

```
"E:\java\MySQL\MySQL Server 8.2\bin\mysql.exe" -uroot -p < "D:\桌面\Java项目AIGC\backend\sql\init_all.sql"
```

3. 输入密码回车
4. **没有任何输出**就是成功了（MySQL 的规矩：成功不说话，失败才报错）

### 这个脚本会做什么

| 顺序 | 动作 |
|---|---|
| 1 | `DROP DATABASE IF EXISTS coursehub` —— **删掉旧库**（有数据会丢！） |
| 2 | 建库 `coursehub`，字符集 utf8mb4 |
| 3 | 建 16 张表 |
| 4 | 插入基础数据：5 个学院、3 个账号、5 门课程、13 个章节、标签、通知 |
| 5 | 插入演示课程「竞赛与创新创业指导」 |

> ⚠️ 它会删库。**已经有数据、只是想让网站跑起来的话，不要执行。**
> 它的用途是"环境坏了，从零重来"。

### 初始化之后还有一步：演示资料要手动传

SQL 只能造出文字数据，造不出 PDF/PPT 文件。
所以初始化后数据库里资料是 0 条，需要你在页面上传（③ 册第 6 节教）。
