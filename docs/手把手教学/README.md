## 二、先建立一张全局地图

一个网站能跑起来，本质是**四个零件连在一起**：

```
   你（浏览器）
        │  输入 http://localhost:8080
        ▼
┌───────────────────────────────────────────┐
│  端口 8080：Spring Boot 后端（Java 程序）   │
│  ┌──────────────┐   ┌──────────────────┐  │
│  │ 托管网页     │   │ 提供 /api/** 接口 │  │
│  │(打包好的前端) │   │(查课程、传文件…)  │  │
│  └──────────────┘   └──────────────────┘  │
└───────┬───────────────────────┬───────────┘
        │                       │
        ▼                       ▼
┌───────────────┐       ┌───────────────┐
│ MySQL 3306    │       │ Redis 6379    │
│ 存所有数据     │       │ 存缓存/分片记录│
│ (用户/课程/资料)│       │ (断电就没了)   │
└───────────────┘       └───────────────┘
```

四个零件对应四件事：

| 零件 | 它是什么 | 为什么需要 | 关掉会怎样 |
|---|---|---|---|
| **MySQL** | 数据库，装在电脑上的服务 | 用户、课程、资料都要存下来 | 网站登录不了，全部接口报错 |
| **Redis** | 内存数据库，也是服务 | 存登录状态缓存、分片上传进度 | 登录、上传功能出错 |
| **Spring Boot 后端** | 你用 IDEA 启动的 Java 程序 | 处理业务逻辑、返回数据 | 网页打不开 |
| **浏览器里的前端** | Vue 写的页面，已打包进后端 | 界面 | —— |

**关键认知**：MySQL 和 Redis 是"装一次、长期在后台跑"的服务；
后端是要你**每次手动启动**的程序。所以日常顺序永远是：

> 确认 MySQL 在跑 → 启动 Redis → 启动后端 → 打开浏览器

## 五、一条命令看懂现在能不能跑

打开 `D:\桌面\Java项目AIGC\tools` 文件夹，**双击 `check-env.bat`**。

窗口会打印 5 项检查结果。正常长这样：

```
[1/5] Java 版本（需要 11）
java version "11.0.5" ...
[2/5] Maven 版本（需要 3.6+）
Apache Maven 3.9.16 ...
[3/5] Node 与 npm（前端需要）
v22.22.2
10.9.7
[4/5] MySQL 端口 3306 是否在监听
  [OK] MySQL 正在运行
[5/5] Redis 端口 6379 是否在监听
PONG
```

- 五项全对 → 直接看第 ② 册
- 有 `[问题]` 或 `Connection refused` → 看第 ① 册对应章节
- 窗口一闪就没了 → 说明 bat 出问题，看第 ⑥ 册 F01

## 六、本手册的三条阅读约定

1. **凡是出现「双击」「点击」的地方，都是真的鼠标动作**，不是比喻。
2. **凡是出现灰色代码块的地方，都是要敲进命令行或用键盘输入的**，一个字符都不要漏。
3. **凡是出现「你应该看到」的地方，是判断你有没有做对的依据**。看不到就停下来查 ⑥ 册。

## 七、这套项目的功能全景（先知道有什么）

| 模块 | 你能做的事 |
|---|---|
| 用户 | 注册、登录、退出、看自己的信息 |
