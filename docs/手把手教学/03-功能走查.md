## 第 1 站：首页（不需要登录）

### 怎么到这里

在浏览器地址栏输入 `http://localhost:8080` 回车。

### 屏幕上有什么（从上往下）

| 位置 | 内容 |
|---|---|
| 顶部导航栏 | 左：`CourseHub` 标志；中：首页 / 课程库 / 资料库；右：登录 / 注册 |
| 大标题区 | 「让课程资料 有序、可信、可追溯」+ 一句话介绍 |

**② 点「浏览课程」**

→ 跳到课程库页面。记住这个感觉，等下还会来。

**③ 点「进入资料库」**

## 第 4 站：课程详情 + 上传资料（核心流程）

### 屏幕上有什么

- 顶部面包屑：课程库 / 竞赛与创新创业指导
- 课程信息区：课程名、编号 CX-101、陈老师、学分、`3 名成员`、`3 份资料`、已加入标记
- 左侧：**「课程简介」** 一段文字
- 右侧或下方：**「课程资料」** 区，带一个搜索框「在本课程内搜索」
- 类型标签行：讲义 / 教材 / 真题 / 笔记 / 作业 / 视频 / 其他
- 一个显眼的 **「上传资料」** 按钮

### 现在做：完整上传一次

点 **「上传资料」**，弹出一个对话框。这个对话框有**三步**，是一步步来的：

#### 第 1 步：选择文件

你会看到一个大虚线框，里面写着：

> 点击选择文件，或把文件拖到这里
> 支持 PDF / Word / PPT / Excel / 图片 / 压缩包，单个文件最大 500MB
> 大文件会自动分片上传

**做**：点这个框 → 弹出文件选择窗口 → 随便选一个 PDF 或 PPT
（比如 `E:\文件办公\PDF` 里的任意一个）

**你应该看到**：文件名出现，然后自动进入第 2 步。

> 如果文件超过 5MB，左上角会显示百分比进度，说明正在**分片上传**。
> 本项目把文件切成 5MB 一片，一片一片传，中途断网可以接着传。

#### 第 2 步：上传文件

这一步是自动的，你会看到进度条从 0% 走到 100%，然后显示 **「上传完成」**。

**特殊现象：秒传**

如果你传的是**库里已经存在的同一个文件**（内容一模一样），
进度条会瞬间到 100%，提示里会出现"秒传"字样。
原理：前端先算文件的 MD5，后端发现这个 MD5 已经存过了，就直接引用旧文件，一个字节都不用传。

#### 第 3 步：填写信息

进度到 100% 后，表单展开，四个字段：

| 字段 | 填什么 | 说明 |
|---|---|---|
| **资料标题** | 比如 `期末复习提纲` | 必填，最长 200 字 |
| **资料类型** | 下拉选「讲义」 | 讲义/教材/真题/笔记/作业/视频/其他 |
| **可见范围** | 下拉选「全平台公开」 | 三个选项，见下表 |
| **资料描述** | 随便写一句 | 选填 |

**可见范围三个选项的区别**（这是本项目的设计亮点之一）：

| 选项 | 谁能看到 |
|---|---|
| 全平台公开 | 所有人，包括没登录的游客 |
| 仅本课程 | 只有这门课的成员和课程负责人 |
| 仅自己可见 | 只有你自己，适合存个人笔记 |

**做**：填好标题，其余用默认，点右下角 **「发布资料」**。

### 你应该看到

- 提示 **「资料发布成功」**
- 对话框关闭
- 资料列表多了一张卡片，就是你刚传的
- 课程页顶部的「N 份资料」数字 +1

> 传完之后，去 `backend\upload\2026\10\17\` 这个目录看，
> 你会看到一堆以 UUID 命名的文件 —— 那就是你刚上传的文件的**真实存放位置**。
> 用 UUID 重命名是为了防"上传一个叫 `../../config.yml` 的恶意文件"。

## 第 5 站：资料库 + 全文检索

### 怎么到这里

点顶部导航 **「资料库」**，或 `http://localhost:8080/#/resources`。

### 屏幕上有什么

- 标题「资料库」+ "在 N 份资料里找到你想要的"
- 大搜索框（占位"输入关键词搜索，例如：数据结构、线性表、期末真题"）+ **「搜索」** 按钮
- 一行 **「热门搜索」** 标签
- 筛选行：全部类型 / 全部课程 / **「重置」**
- 结果计数：`N 条结果`
- 资料卡片：标题、类型标签、评分、下载次数、上传者、描述

### 现在做

**① 搜一个词**

在搜索框输入 `竞赛` → 点 **「搜索」**。

**你应该看到**：`1 条结果`，就是「南京信息工程大学2026年学生创新创业竞赛目录」。

> 这里的搜索用 MySQL 的 **FULLTEXT 中文分词索引**（ngram），
> 不是 `LIKE '%竞赛%'`。后者会让索引失效、数据一多就慢得离谱。

**② 搜一个不存在的词**

输入 `量子力学` → 搜索 → 会显示 **「没有找到与"量子力学"相关的资料」** + 「清空筛选条件」。

**③ 点开一份资料**

## 第 6 站：资料详情（功能最多的一页）

### 屏幕上有什么

| 区域 | 内容 |
|---|---|
| 左/上 | 资料标题、类型标签、可见范围标签 |
| 数据条 | 可信度评分 `60.75`、下载次数、查看次数、收藏数、评论数 |
| 主按钮 | **「下载」** |
| 次按钮 | **「上传新版本」**、**「收藏」**、**「举报」** |
| 信息区 | 上传者昵称、上传时间、所属课程、章节 |
| 描述区 | 你填的资料描述 |
| 两个标签页 | **「版本历史」**、**「讨论区」** |

### 现在做（6 个小实验）

#### 实验 1：下载

点 **「下载」**。

**你应该看到**：浏览器左下角/右上角出现下载提示，提示文字 **「下载已开始」**，
文件被保存到你的「下载」文件夹。

> 如果没登录，会提示 **「请先登录后再下载」**。

#### 实验 2：收藏

点 **「收藏」** → 提示收藏成功，按钮变成已收藏状态。
再点一次 → 取消收藏。

#### 实验 3：评论（含楼中楼）

1. 点 **「讨论区」** 标签
2. 在输入框里写一句：`这份资料的第 3 页有个表格很有用`
3. 点 **「发表」**（或「评论」）按钮
4. 提示 **「评论成功」**，评论出现在下方

**再试试回复**：点你那条评论下面的 **「回复」** →
写 `补充：第 5 页还有一个公式` → 发送 → 提示 **「回复成功」**。

**你会看到**：回复缩进显示在父评论下面 —— 这就是"两级评论"。
（只能两级，回复的回复会挂到同一个父评论下，这是刻意的设计，避免无限嵌套。）

**删除试试**：点自己评论旁的删除图标 → 弹出 **「确定删除这条评论吗？」** → 点 **「确定删除」** → 提示 **「已删除」**。

#### 实验 4：上传新版本（版本树的核心）

1. 点 **「上传新版本」**
2. 弹出对话框，显示 **「当前版本为 V1」**，提示"上传后会生成 V2，历史版本会完整保留"
3. 选一个文件（跟之前不同的文件）
4. 填 **「变更说明」**：`修正了几个错别字`
5. 点 **「上传并生成新版本」**
6. 提示 **「新版本已生成」**

现在回去点 **「版本历史」** 标签，你会看到两行记录，右边有 **「下载」** 和 **「回滚到此版本」**。

#### 实验 5：回滚

在 V1 那行点 **「回滚到此版本」** →
弹出 **「确定回滚到 V1 吗？」**，并说明"回滚不会删除任何历史版本，而是以该版本的内容生成一个新版本" →
点 **「确定回滚」** → 提示 **「已回滚（已生成新版本）」**。

**关键理解**：回滚不是"把 V2 删掉回到 V1"，而是**用 V1 的内容再生成一个 V3**。
所有历史都留着，谁在什么时候干了什么，一眼看得清。

#### 实验 6：举报

1. 点 **「举报」**
2. 弹出对话框：**「举报原因」** 下拉（选一个）、**「补充说明」** 文本框
3. 提示文字："同一对象在管理员处理前只能举报一次，请如实填写。"
4. 点 **「提交举报」**
5. 提示 **「举报已提交，我们会尽快处理」**

> 现在库里就有你刚提交的举报，等下第 8 站用管理员账号处理它。

## 第 8 站：管理员功能（换账号）

### 8.1 退出登录

点右上角昵称 → **「退出登录」** → 提示 **「已退出登录」**。

### 8.2 用管理员登录

### 8.3 进举报处理

点右上角昵称 → **「举报处理」**
（或地址 `http://localhost:8080/#/admin/reports`）

### 屏幕上有什么

- 标题「举报处理」+ "核实用户提交的举报，并给出处理结论"
- 状态标签页：**待处理** / **全部** / **已处理** / **已驳回**
- 举报卡片：被举报对象标题、举报原因、补充说明、举报人、时间
- 每张卡有两个按钮：**「查看被举报资料」**、**「处理该举报」**

### 现在做

1. 在 **「待处理」** 标签下找到你第 6 站提交的那条举报
2. 点 **「处理该举报」**
3. 弹窗里：
   - **被举报对象**：显示资料标题
   - **处理结论**：两个选项「属实，已处理」/「不属实，驳回」
   - **处理说明**：填 `测试数据处理` 
4. 点 **「确认处理」**
5. 提示 **「处理完成」**，这条举报从「待处理」消失，跑到「已处理」或「已驳回」标签下

> 用普通学生账号（`2025210101`）打开这个地址，会看到
> **「需要管理员权限」**「举报处理页面仅对管理员开放。当前账号没有该权限。」+「返回首页」按钮。
> 这说明**前端有权限提示、后端有角色拦截**，双保险。

| 困惑 | 解释 |
|---|---|
| 为什么上传后 `upload` 目录里文件名是乱的？ | 用 UUID 重命名，防路径穿越攻击。原名存在数据库 `file.original_name` 字段里 |
| 为什么资料评分都是 60.75？ | 因为 3 份资料都是"刚上传、0 下载、0 评论"，五项因子算出来必然一样。传得越多、被下载越多，分数才会分化 |
| 为什么评论只能两级？ | 无限嵌套在 UI 上会越来越窄，实际没人看。两级（主评论 + 回复）覆盖 95% 场景 |
| 为什么回滚要生成新版本？ | 保证"任何一次内容变更都可追溯"。删版本就意味着历史出现空洞 |
| 为什么首页的"查看次数"和"下载次数"不一样？ | 打开详情页算一次查看，点下载才算一次下载。查看走 Redis 异步累加，不锁数据库行 |
