# 接口清单（API 文档）

> 本文列出系统所有对外接口的**路径、参数、返回、错误码**。
> 面向零基础的读者，重点讲**每个接口是干什么的、参数怎么传**。
>
> - 后端端口：`8080`（本地开发）
> - 前端开发端口：`5173`（通过 Vite 代理访问后端）
> - 在线调试页面：启动后端后访问 `http://localhost:8080/doc.html`（Knife4j）

---

## 一、先懂三条"通用规则"

在看具体接口之前，先记住这三条。所有接口都遵守，后面不再重复。

### 规则 1：所有接口返回同一个结构

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "timestamp": 1759300000000
}
```

| 字段 | 含义 |
|---|---|
| `code` | 业务状态码。**`0` 表示成功**，非 0 都是失败 |
| `message` | 提示信息，成功时是 `ok`，失败时是给用户看的原因 |
| `data` | 业务数据。失败时为 `null` |
| `timestamp` | 服务器时间戳 |

**为什么必须统一**：如果每个接口返回结构都不一样，前端就得为每个接口写一套解析代码。统一之后，前端的 `request.js` 拦截器统一处理——`code === 0` 就把 `data` 交给页面，否则弹错误提示。业务代码里完全不用管这层。

### 规则 2：错误码分段

| 段位 | 含义 | 举例 |
|---|---|---|
| `0` | 成功 | — |
| `400xx` | 参数/请求错误 | `40001` 参数校验失败 |
| `401xx` | 认证问题 | `40101` 未登录 / `40104` 账号或密码错误 |
| `403xx` | 权限不足 | `40301` 无权执行该操作 |
| `404xx` | 资源不存在 | `40403` 课程不存在 |
| `409xx` | 状态冲突 | `40906` 你已经加入该课程了 |
| `410xx` | 文件相关 | `41002` 文件超出大小限制 |
| `500xx` | 服务端错误 | `50000` 系统繁忙 |

**这么分段的好处**：看到一个码就知道该找谁——`4xxxx` 是调用方的问题，`5xxxx` 是服务端的问题。

### 规则 3：需要登录的接口要带 Token

登录成功后，接口返回一个 `token`。之后请求**需要登录的接口**时，要把它放进请求头：

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEs...
```

> 前端不用手写这行 —— `request.js` 的请求拦截器会自动从 localStorage 取出 Token 并加上去。

**如何判断接口要不要登录**：下文每个接口都标了「是否需要登录」。

## 三、认证与用户（AuthController）

### 3.1 用户登录

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/auth/login` |
| 是否需要登录 | ❌ 否（登录本身当然不需要先登录） |
| 作用 | 校验账号密码，签发 JWT 令牌 |

**请求体**

```json
{
  "username": "admin",
  "password": "admin123"
}
```

| 参数 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| `username` | string | ✅ | 3-50 个字符 |
| `password` | string | ✅ | 6-50 个字符 |

**成功返回**

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 604800,
    "user": {
      "id": 1,
      "username": "admin",
      "nickname": "系统管理员",
      "role": "ADMIN",
      "creditScore": 100,
      "level": 5
    }
  }
}
```

> `expiresIn` 单位是秒，604800 秒 = 7 天。
> **注意 `user` 里没有 `password` 字段** —— 这是 Entity → VO 转换的结果，密码永远不会出现在响应里。

**可能的错误**

| code | 场景 |
|---|---|
| `40001` | 账号或密码为空/长度不对 |
| `40104` | 账号不存在 **或** 密码错误（**故意用同一个码**） |
| `40105` | 账号已被封禁 |

> ⚠️ **为什么"账号不存在"和"密码错误"返回同一个码？**
> 这叫**防用户枚举**。如果两者提示不同，攻击者就能靠"提示变化"批量试探出哪些账号是真实的。统一提示后，他无法区分。

### 3.2 用户注册

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/auth/register` |
| 是否需要登录 | ❌ 否 |
| 作用 | 创建新账号 |

**请求体**

```json
{
  "username": "2025210001",
  "password": "123456",
  "nickname": "王同学",
  "studentNo": "2025210001",
  "collegeId": 1,
  "email": ""
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | ✅ | 3-50 字符，唯一 |
| `password` | string | ✅ | 6-50 字符 |
| `nickname` | string | ✅ | 昵称 |
| `studentNo` | string | ❌ | 学号 |
| `collegeId` | number | ❌ | 所属学院 ID（下拉框来自 `GET /api/colleges`） |
| `email` | string | ❌ | 邮箱 |

**成功返回**

```json
{ "code": 0, "message": "注册成功", "data": 1 }
```

> `data` 是新用户的 ID。

**可能的错误**

| code | 场景 |
|---|---|
| `40001` | 参数校验失败 |
| `40106` | 该账号已被注册 |

> **新注册用户默认值**：角色 `STUDENT`、信用分 `100`、等级 `1`、状态 `ACTIVE`。
> **密码入库前会经 BCrypt 加密**，数据库里存的是 `$2a$10$...` 这样的哈希，不是明文。

### 3.3 获取当前登录用户信息

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/auth/me` |
| 是否需要登录 | ✅ **是** |
| 作用 | 拿到"我是谁"。刷新页面后恢复登录状态用 |

**请求**

```
GET /api/auth/me
Authorization: Bearer <token>
```

**成功返回**

```json
{
  "code": 0,
  "data": {
    "id": 1,
    "username": "admin",
    "nickname": "系统管理员",
    "role": "ADMIN",
    "creditScore": 100,
    "level": 5,
    "status": "ACTIVE"
  }
}
```

> **注意**：这个接口**不需要前端传用户 ID**。后端从 Token 里解析出"你是谁"，前端传什么都会被忽略（传了也不可信）。这是安全设计的基本要求。

**可能的错误**

| code | 场景 |
|---|---|
| `40101` | 未登录 / Token 无效 / Token 过期 |

### 3.4 退出登录

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/auth/logout` |
| 是否需要登录 | ✅ 是 |
| 作用 | 清除登录状态 |

**返回**：`{"code":0,"message":"已退出登录","data":null}`

> **注意**：JWT 是"无状态"的，服务端不保存登录记录，所以严格来说前端把本地 Token 删掉就等于退出了。
> 这个接口目前只做日志记录。"强制下线"（管理员踢人）需要把 Token 加入 Redis 黑名单，计划在 M3 阶段实现。

## 五、课程（CourseController）

### 5.1 课程列表（分页 + 筛选）

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/courses` |
| 是否需要登录 | ❌ 否（未登录也能浏览有哪些课） |
| 作用 | 分页查询课程，支持关键词/学院/学期/状态筛选 |

**Query 参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `page` | number | ❌ | 1 | 页码，从 1 开始 |
| `pageSize` | number | ❌ | 10 | 每页条数，**最大 100**（超出会被强制截断） |
| `keyword` | string | ❌ | — | 匹配课程名或教师名 |
| `collegeId` | number | ❌ | — | 按学院筛选 |
| `term` | string | ❌ | — | 按学期筛选，如 `2026-2027-1` |
| `status` | string | ❌ | — | `DRAFT` / `PUBLISHED` / `ARCHIVED` |

**请求示例**

```
GET /api/courses?page=1&pageSize=9&keyword=数据结构&collegeId=1
```

**返回示例**

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 1,
        "courseCode": "DS-204",
        "name": "数据结构与算法",
        "collegeId": 1,
        "collegeName": "计算机学院",
        "teacher": "张老师",
        "term": "2026-2027-1",
        "credit": 3.5,
        "description": "讲授线性表、树、图等基础数据结构",
        "ownerId": 1,
        "memberCount": 25,
        "resourceCount": 8,
        "status": "PUBLISHED",
        "createdAt": "2026-10-01 10:00:00"
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 9,
    "pages": 1
  }
}
```

> **`collegeName` 从哪来**：数据库里只存了 `collegeId`，但前端要显示"计算机学院"。后端 SQL 用 `LEFT JOIN sys_college` 一次把名字带出来，前端拿到就能直接渲染，不用再查一次。

> **`pageSize` 为什么有上限**：如果前端传 `pageSize=999999`，数据库要一次吐出全部数据，内存和网络都会被拖垮。`PageQuery` 里做了 `Math.min(pageSize, 100)` 保护。

### 5.4 创建课程

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/courses` |
| 是否需要登录 | ✅ 是 |
| 作用 | 新建一门课程 |

**请求体**

```json
{
  "name": "数据结构与算法",
  "courseCode": "DS-204",
  "collegeId": 1,
  "teacher": "张老师",
  "term": "2026-2027-1",
  "credit": 3.5,
  "description": "讲授线性表、树、图等基础数据结构"
}
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `name` | string | ✅ | 最长 100 字符 |
| `courseCode` | string | ❌ | 最长 30 字符 |
| `collegeId` | number | ❌ | 学院 ID |
| `teacher` | string | ❌ | 最长 50 字符 |
| `term` | string | ❌ | 最长 30 字符 |
| `credit` | number | ❌ | 0 ~ 99.9 |
| `description` | string | ❌ | 最长 2000 字符 |
| `status` | string | ❌ | 不传默认 `PUBLISHED` |

**成功返回**：`{"code":0,"message":"课程创建成功","data":5}`（`data` 是新课程 ID）

**后端自动做的事**

1. `ownerId` 自动设为**当前登录用户**（前端传什么都无效，防止伪造负责人）
2. `memberCount` 初始化为 `1`（创建者自己）
3. **创建者自动成为课程成员**，课程内角色为 `OWNER`
   （第 2、3 步在同一个事务里，要么都成功、要么都回滚，不会出现"课程建好了但没加进成员表"的中间状态）

**可能的错误**

| code | 场景 |
|---|---|
| `40001` | 课程名称为空等 |
| `40101` | 未登录 |

### 5.5 修改课程

| 项目 | 内容 |
|---|---|
| 路径 | `PUT /api/courses/{id}` |
| 是否需要登录 | ✅ 是 |
| **权限** | **仅课程负责人或管理员** |
| 作用 | 修改课程信息 |

**请求体**：同 5.4（只传要改的字段，未传的字段保持不变）

**返回**：`{"code":0,"message":"课程已更新","data":null}`

**可能的错误**

| code | 场景 |
|---|---|
| `40301` | **你不是这门课的负责人**（越权） |
| `40403` | 课程不存在 |
| `40101` | 未登录 |

> ⚠️ **这是"数据权限"的典型例子**
> 接口本身只要求"登录"，任何登录用户都能调用。但"能不能改**这门**课"是另一回事。
> 如果不在 Service 层校验 `course.ownerId == 当前用户`，那么任何登录用户只要把 URL 里的 ID 一改，就能改掉别人的课程——这叫**水平越权漏洞**。
>
> **功能权限**（能不能进接口）靠拦截器 + 注解；
> **数据权限**（能不能动这条数据）必须在 Service 层按数据归属判断。
> 两者缺一不可。

### 5.6 删除课程

| 项目 | 内容 |
|---|---|
| 路径 | `DELETE /api/courses/{id}` |
| 是否需要登录 | ✅ 是 |
| **权限** | **仅课程负责人或管理员** |
| 作用 | 删除课程 |

**返回**：`{"code":0,"message":"课程已删除","data":null}`

> **这是"逻辑删除"**：数据库里只把 `is_deleted` 改成 1，数据仍在。列表接口会过滤掉，用户看不出差别，但管理员可以恢复，且不会破坏"资料→课程"的关联关系。

### 5.7 加入课程

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/courses/{id}/join` |
| 是否需要登录 | ✅ 是 |
| 作用 | 当前用户加入指定课程 |

**返回**：`{"code":0,"message":"已加入课程","data":null}`

**可能的错误**

| code | 场景 |
|---|---|
| `40906` | 你已经加入该课程了 |
| `40403` | 课程不存在 |

> **防重复加入的两道防线**：
> 1. Service 层先查一次"是不是已加入"，是就返回提示
> 2. 数据库 `course_member` 表对 `(course_id, user_id)` 建了**唯一索引**——就算并发请求绕过第 1 步，数据库也会拒绝插入重复记录
>
> 只靠第 1 步是不够的：两个请求同时到达时，两边都查不到记录，然后都去插入，就会产生脏数据。唯一索引是最后一道保险。

---

## 六、文件（FileController）

### 6.1 上传文件

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/files/upload` |
| 是否需要登录 | ✅ 是 |
| 请求格式 | `multipart/form-data` |
| 表单字段名 | `file` |
| 作用 | 上传文件，服务端做**五重安全校验**并尝试**秒传** |

**请求示例**

```bash
curl -X POST http://localhost:8080/api/files/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@D:/课件/数据结构.pdf"
```

**成功返回**

```json
{
  "code": 0,
  "message": "上传成功",
  "data": {
    "id": 12,
    "fileName": "数据结构课件.pdf",
    "fileExt": "pdf",
    "fileSize": 2621440,
    "mimeType": "application/pdf",
    "storageType": "LOCAL",
    "uploaderId": 1,
    "downloadUrl": "/api/files/12/download",
    "instantUpload": false,
    "readableSize": "2.50 MB"
  }
}
```

**`instantUpload` 字段的含义**

| 值 | 含义 |
|---|---|
| `false` | 常规上传，文件真实写入了磁盘 |
| `true` | **秒传命中** —— 服务端已有相同文件（MD5 相同），只建立引用，没有真实上传 |

**可能的错误**

| code | 场景 |
|---|---|
| `41001` | 上传文件为空 |
| `41002` | 文件超出大小限制（默认 500MB） |
| `41003` | 不支持的文件类型 —— 扩展名不在白名单，**或文件内容与扩展名不符** |
| `41004` | 文件上传失败（IO 异常） |
| `40101` | 未登录 |

> **41003 的两种 message 要分清**：
> - `不支持的文件类型：exe` —— 扩展名就被拦了
> - `文件内容与扩展名不符，已拒绝上传` —— 扩展名是合法（如 pdf），但文件头不是 PDF，是伪装文件
>
> 五重校验的完整原理见 `docs/文件上传与存储设计.md`。

### 6.2 查询文件元信息

|---|---|
| 路径 | `GET /api/files/{id}` |

### 6.3 下载文件

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/files/{id}/download` |
| 是否需要登录 | ✅ 是 |
| 响应类型 | **文件流**（不是 JSON 统一响应体） |

**响应头示例**

```
Content-Type: application/pdf
Content-Disposition: attachment; filename*=UTF-8''%E8%AF%BE%E4%BB%B6.pdf
Content-Length: 2621440
```

> **`filename*=UTF-8''...` 是什么**：HTTP 响应头只能放 ASCII 字符，中文文件名必须按
> RFC 5987 编码。浏览器看到这个格式会自动还原成中文名。不做这一步，下载下来的文件名就是乱码。

> **为什么这个接口不返回 `Result` 包装**：它的响应体就是文件内容本身。
> 若再包一层 JSON，浏览器下载到的就是一段 JSON 文本，而不是文件。

### 6.4 删除文件

| 项目 | 内容 |
|---|---|
| 路径 | `DELETE /api/files/{id}` |
| 是否需要登录 | ✅ 是 |
| 作用 | 引用计数减 1；**只有归零时才真正删除物理文件和数据库记录** |

**返回**：`{"code":0,"message":"删除成功","data":null}`

> **同一份文件可能被多份资料引用**（秒传导致的）。
> 删除一次只表示"取消我这一份引用"，文件必须保留给其他资料继续用。
> 这个机制叫**引用计数**，详见 `docs/文件上传与存储设计.md` 第七节。

## 七、资料（ResourceController）

> **本模块的核心是「三级可见性」**：每份资料可设为全平台公开 / 仅本课程 / 仅自己。
> 服务端在**每次读取和写入时**都会校验，权限过滤直接写在 SQL 里。

### 7.1 资料列表（已按可见性过滤）

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/resources` |
| 是否需要登录 | ❌ 否（但**返回结果按可见性过滤**，游客只能看到 PUBLIC） |

**Query 参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `page` / `pageSize` | number | 分页，pageSize 上限 100 |
| `courseId` | number | 按课程筛选 |
| `uploaderId` | number | 按上传者筛选 |
| `type` | string | `TEXTBOOK`/`LECTURE`/`EXAM`/`NOTES`/`ASSIGNMENT`/`VIDEO`/`OTHER` |
| `visibility` | string | `PUBLIC`/`COURSE_ONLY`/`PRIVATE` |
| `status` | string | `PENDING`/`PUBLISHED`/`REJECTED`/`OFFLINE` |
| `keyword` | string | 匹配标题或描述 |

**返回示例**

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 1,
        "courseId": 1,
        "courseName": "数据结构与算法",
        "uploaderId": 1,
        "uploaderName": "系统管理员",
        "title": "第二章 线性表",
        "description": "含顺序表与链表",
        "type": "LECTURE",
        "visibility": "PUBLIC",
        "status": "PUBLISHED",
        "score": 0.00,
        "downloadCount": 0,
        "viewCount": 1,
        "fileId": 1,
        "fileName": "线性表讲义.pdf",
        "fileExt": "pdf",
        "fileSize": 2621440,
        "readableSize": "2.50 MB",
        "downloadUrl": "/api/resources/1/download",
        "canEdit": true
      }
    ],
    "total": 1, "page": 1, "pageSize": 10, "pages": 1
  }
}
```

> **`canEdit`** 是服务端算好的"当前用户能不能改这条"。
> 前端据此显示/隐藏编辑按钮即可，不用自己在页面里重复判断权限逻辑。

### 7.2 资料详情

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/resources/{id}` |
| 是否需要登录 | ❌ 否（但受可见性限制） |
| 副作用 | 会把 `view_count` +1 |

**可能的错误**

| code | 场景 |
|---|---|
| `40404` | 资料不存在 |
| `40303` | 无权访问（如他人的 PRIVATE 资料） |
| `40304` | 你不是该课程成员（COURSE_ONLY 资料） |
| `40101` | 未登录且访问的是非 PUBLIC 资料 |

> **40303 与 40304 为什么要分开**：
> - `40303` = "这是别人的私密资料"
> - `40304` = "这资料限本课程，你没加入这门课"
>
> 分开返回能让前端给出更准确的提示（"申请加入课程" vs "无权访问"）。

### 7.3 发布资料

| 项目 | 内容 |
|---|---|
| 路径 | `POST /api/resources` |
| 是否需要登录 | ✅ 是 |
| 作用 | 把已上传的文件挂到课程下，正式成为一份资料 |

> **注意：发布资料是"两步走"**
> ```
> ① POST /api/files/upload   → 得到 fileId
> ② POST /api/resources      → 传 fileId + courseId + title
> ```
> 分开的好处：大文件可以先慢慢传，传完再填标题；秒传时第二步只需毫秒。

**请求体**

```json
{
  "courseId": 1,
  "chapterId": null,
  "fileId": 12,
  "title": "第二章 线性表 讲义",
  "description": "含顺序表与链表的对比",
  "type": "LECTURE",
  "visibility": "COURSE_ONLY"
}
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `courseId` | ✅ | 所属课程 |
| `fileId` | ✅ | 上传接口返回的文件 ID |
| `title` | ✅ | 最长 200 字符 |
| `chapterId` | ❌ | 章节（可不填） |
| `description` | ❌ | 最长 2000 字符 |
| `type` | ❌ | 默认 `OTHER` |
| `visibility` | ❌ | 默认 `PUBLIC` |

**成功返回**：`{"code":0,"message":"发布成功","data":8}`

**后端自动做的事**

1. 校验课程、文件是否存在
2. 插入 `resource` 记录（上传者 = 当前登录用户）
3. **生成 v1 版本记录**，指向该文件
4. 把 `current_version_id` 指到 v1
5. **课程的 `resource_count` +1**

> 第 2~5 步在**同一个事务**里，要么全成功要么全回滚，
> 不会出现"资料建好了但没有版本"这种中间状态。

### 7.4 修改资料

| 项目 | 内容 |
|---|---|
| 路径 | `PUT /api/resources/{id}` |
| 是否需要登录 | ✅ 是 |
| **权限** | 上传者 / 课程负责人 / 管理员 |

**请求体**：同 7.3（PUT 是全量更新，必填字段要一起传）

**可能的错误**：`40301` 无权执行该操作

### 7.5 删除资料

| 项目 | 内容 |
|---|---|
| 路径 | `DELETE /api/resources/{id}` |
| 是否需要登录 | ✅ 是 |
| **权限** | 上传者 / 课程负责人 / 管理员 |
| 副作用 | 逻辑删除；课程 `resource_count` -1；释放文件引用（引用计数 -1） |

### 7.6 下载资料文件

| 项目 | 内容 |
|---|---|
| 路径 | `GET /api/resources/{id}/download` |
| 是否需要登录 | ✅ 是 |
| 响应类型 | 文件流 |
| 副作用 | `download_count` +1 |

> **下载前也会校验可见性**。否则私密资料只要猜到 ID，
> 就能绕过详情接口直接下载，前面的校验就白做了。

## 九、怎么自己试这些接口

### 方式一：用 Knife4j 网页（推荐新手）

```
1. 启动后端：cd backend && mvn spring-boot:run
2. 浏览器打开：http://localhost:8080/doc.html
3. 左侧找到「01-认证与用户」→「用户登录」
4. 点「调试」，填入 admin / admin123，点「发送」
5. 复制返回的 token
6. 右上角「文档管理」→「全局参数」→ 添加 Authorization: Bearer <token>
7. 之后就能调需要登录的接口了
```

### 方式二：用命令行

```bash
# 1. 登录拿 Token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}"

# 2. 带 Token 访问
curl http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <上一步拿到的token>"

# 3. 查询课程列表
curl "http://localhost:8080/api/courses?page=1&pageSize=5&keyword=数据"
```

### 方式三：跑自动化测试脚本

项目里已备好脚本，会自动跑完所有场景并打印结果：

```bash
cd backend && bash verify-m1.sh        # 认证模块（14 项）
cd backend && python test-course.py    # 课程模块
```
