### 3.2 分层架构——每层负责什么

这是**后端最重要的概念**。请求从浏览器进来，会依次穿过这几层：

```
浏览器请求
   ↓
【Controller 接口层】  只做三件事：收参数、校验、调 Service
   职责：接收 HTTP 请求，返回统一响应体
   禁止：写业务逻辑、直接操作数据库
   ↓
【Service 业务层】      真正干活的地方
   职责：业务规则、事务控制、权限校验、跨表编排
   禁止：拼 SQL
   ↓
【Mapper 数据访问层】   只跟数据库打交道
   职责：执行 SQL，把结果映射成 Java 对象
   禁止：写业务判断
   ↓
【MySQL 数据库】
```

**为什么非要分层**：如果所有代码都写在 Controller 里，半年后你想换个接口地址，就得把业务逻辑一起翻出来改。分层之后，改接口不影响业务，改业务不影响数据库。

| 目录 | 属于哪层 | 放什么 |
|---|---|---|
| `controller/` | 接口层 | `XxxController.java` |
| `service/` + `service/impl/` | 业务层 | 接口 + 实现类 |
| `mapper/` | 数据访问层 | Mapper 接口（XML 在 resources/mapper） |
| `entity/` | 数据模型 | 与数据库表一一对应 |
| `dto/` | 数据模型 | 前端传来的参数 |
| `vo/` | 数据模型 | 返回给前端的数据 |

> **为什么 Entity / DTO / VO 要分三个**
> `entity` 里有 `password` 字段。如果直接把它返回给前端，密码就泄露了。
> 所以返回前必须转成 `vo`，只挑能给的字段。

### 3.3 后端文件逐个说明

#### 🔴 核心文件（必须理解）

| 文件 | 作用 | 关键点 |
|---|---|---|
| `pom.xml` | 项目的「零件清单」 | 声明要哪些依赖库。想加新功能先来这里加依赖 |

| `sql/schema.sql` | 建表脚本 | 16 张表的完整定义，含索引和全文检索配置 |

> 前端跑在 5173，后端跑在 8080。浏览器认为这是「跨域」，会拦截请求。
> 配了代理后，前端代码里写 `/api/health` 就行，代理会帮你转到后端，
> 浏览器以为是同源，就不拦截了。

## 八、常见问题

**Q：我只想跑起来看看，最少要动哪几个文件？**

1. `backend/src/main/resources/application-local.yml` — 填你的数据库密码
2. 建库：`mysql -uroot -p < backend/sql/schema.sql`
3. 启动后端：`mvn spring-boot:run`
4. 启动前端：`cd frontend && npm install && npm run dev`

**Q：改了代码后怎么重新编译？**

后端：`mvn clean compile`；前端：`npm run dev` 会自动热更新。

**Q：`target/` 目录是干嘛的？能删吗？**

是编译产物，能删。执行 `mvn clean` 就会清掉，下次编译重新生成。

**Q：为什么后端有 `entity`、`dto`、`vo` 三个长得差不多的目录？**

因为它们用途不同：
- `entity` — 数据库长什么样
- `dto` — 前端传进来什么
- `vo` — 返回给前端什么

分开是为了**安全**（不泄露密码）和**灵活**（前端字段可以和后端表结构不一致）。
