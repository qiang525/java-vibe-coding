### 4.5 修掉一个 bat 隐藏 bug（实测发现）

`tools/start-backend.bat` 里原本有一行提示：

```
echo   启动顺序：MySQL(常驻) -> Redis -> 后端
```

cmd 会把 `->` 里的 `>` 当成**输出重定向**，于是：
- 运行时凭空生成了一个 29 字节的垃圾文件 `backend\后端`
- 那句提示语根本没有打印出来

**已修复**：改成 `MySQL(常驻) 然后 Redis 然后 后端`，并复测确认不再产生垃圾文件。
这个坑已写进 `06-故障排查.md` 的 F01。

## 五、遗留问题清单

按影响程度分级：**P1 影响使用 / P2 影响体验 / P3 功能缺口但不影响主流程**

### R1（P3）站内通知只有表，没有接口和页面

`notification` 表建了、种子数据也有，但没有 Controller，前端也没有铃铛图标。
`GET /api/notifications` 返回 404。

**影响**：不影响任何现有功能。
**补的话**：加一个 `NotificationController`（列表/已读/全部已读）+ 顶栏铃铛组件，约半天。

### R2（P3）下载记录没有展示入口

`download_record` 表存在，下载时会记录，但没有"我的下载"页面。

**影响**：数据在，只是看不到。
**补的话**：一个页面 + 一个接口，约 2 小时。

### R3（P3）标签功能未接入前端

`tag` 表有 8 个标签、`resource_tag` 关联表也在，但发布资料时没有选标签的界面，
资料库也没有"按标签筛选"。

**影响**：标签目前是"死数据"。
**补的话**：上传对话框加多选标签 + 列表加标签筛选，约 3 小时。

### R4（P3）没有个人中心

用户改不了昵称、改不了密码、换不了头像。
只能通过数据库 SQL 改。

**影响**：不影响浏览和上传。
**补的话**：个人中心页 + 2 个接口，约 2 小时。

### R5（P3）没有管理员数据看板

管理员只能处理举报和看审计日志，看不到"总用户数/今日上传/热门课程"这类统计。

**影响**：纯展示功能缺失。
**补的话**：一个统计接口 + 一个页面，约 3 小时。

### R6（P3）章节只读，不能在页面上增删改

课程详情页能展示章节，但没有"新增章节/编辑章节"的按钮。
章节目前只能通过数据库或 SQL 维护。

**影响**：创建新课程后，章节需要手工插库。
**补的话**：章节管理弹窗 + 3 个接口，约 3 小时。

### R7（P3）没有自动化单元测试

项目里 `backend/test-*.py` 是我写的**接口集成验证脚本**（跑真实 HTTP 请求），
不是 JUnit 单元测试，也不在 `mvn test` 里跑。

**影响**：改代码后没有回归测试保护。
**补的话**：给 Service 层加 JUnit + Mockito，约 1-2 天。

### R8（P3）定时评分任务只在凌晨 3 点跑

`ResourceScoreTask` 的 cron 是 `0 0 3 * * ?`（每天 03:00）。
白天新上传的资料评分是 0，要等第二天凌晨才会算出来。

**影响**：白天上传后看到的评分是 0，容易误以为算错了。
**临时办法**：管理员调一次 `POST /api/admin/recalc-score` 立即重算。
**彻底办法**：发布资料时同步算一次初值（或在页面加"刷新评分"按钮）。

## 七、结论

**核心功能全部可用**，可以：
- 直接演示（只启后端，8080 一个地址）
- 继续开发（前后端分离 + 热更新）
- 上传 GitHub（无明文凭据、无构建产物）

**7 个遗留问题都是"锦上添花"，没有一个会阻塞使用。**
建议的学习顺序：先把 7 册手把手文档走完，再挑 R4（个人中心）或 R3（标签）练手，
因为它们涉及"新增表字段 → 新增接口 → 新增页面"的完整链路，最适合当第二个项目练习。
