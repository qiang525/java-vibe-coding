# 前端设计系统与界面升级说明

> 本文讲清楚：这次「把前端做得更高级」具体做了什么、每一处为什么这么改。
> 你可以把它当成一份**前端设计入门手册**来读 —— 不讲玄学，只讲可复用的规则。

---

## 一、先说结论：升级了哪几层

前端"高级感"不是靠图片和特效堆出来的，而是三层东西：

| 层次 | 解决的问题 | 本次做法 |
|---|---|---|
| **① 设计令牌** | 颜色、圆角、阴影、动效处处不一致，显得杂 | 全部收进 `:root` 变量，改一处全站生效 |
| **② 组件规范** | 按钮/卡片/输入框各写各的样式 | 统一由全局样式 + Element Plus 主题变量控制 |
| **③ 页面编排** | 布局松散、层次不清、等待时白屏 | Hero 区、信息栅格、骨架屏、空状态、响应式 |

一句话：**先建规则，再写页面**。这样后面加 10 个页面也不会失控。

## 二、设计令牌（Design Tokens）—— 最关键的一层

文件：`src/styles/main.css`

### 2.1 为什么需要"令牌"

假设没有令牌，每个页面各自写：

```css
/* 首页 */  color: #409eff;
/* 登录页 */ color: #337ecc;   ← 差一点点
/* 卡片 */  border-radius: 12px;
/* 弹窗 */  border-radius: 16px;  ← 又不一样
```

用户看到的就是"说不上哪里怪，但就是不精致"。
把所有会变的值提取成变量后：

```css
:root {
  --ch-primary: #4f46e5;
  --ch-radius-lg: 16px;
  --ch-shadow-md: 0 12px 32px rgba(15, 23, 42, 0.09);
}
```

**改主色只需改一行**，全站 30 多个文件同步生效。

### 2.2 本次定的几组令牌

**① 品牌色：从"标准蓝"换成"靛蓝 → 紫罗兰"**

```
原来：#409eff  （Element Plus 默认蓝，几乎所有后台系统都用它）
现在：#4f46e5 → #7c3aed → #a855f7 （靛蓝渐变到紫罗兰）
```

为什么不继续用蓝色？因为**默认蓝太"通用"了**，看起来像模板。
靛蓝偏紫，观感更沉稳、更有设计感，同时保留了"科技/理性"的调性。

**② 中性色：从"纯灰"换成"冷石板灰"**

```
原来：文字 #303133 / 边框 #dcdfe6   （偏暖的纯灰）
现在：文字 #0f172a / 边框 #e2e8f0   （偏冷的石板灰 slate）
```

冷色调的灰与靛蓝主色更协调，页面整体更"干净"。

**③ 阴影分四层**

```
--ch-shadow-sm   卡片默认
--ch-shadow      普通浮起
--ch-shadow-md   悬停/hover
--ch-shadow-lg   对话框、登录卡片
```

规则：**元素在视觉上"越高"，阴影越大越柔和**。
这样用户的潜意识能判断出"哪个东西是可以点的、哪个是浮在上层的"。

**④ 动效统一用一条曲线**

```css
--ch-ease: cubic-bezier(0.22, 1, 0.36, 1);
```

这条曲线特点是**起步快、收尾缓**，观感上"跟手、有质感"。
所有过渡都引用它，避免每个组件各写一个 `ease-in-out` 导致节奏不一致。

## 三、Element Plus 主题覆盖

文件：`src/styles/main.css` 第二节

Element Plus（组件库）的全部颜色都从一组 CSS 变量推导。所以只要改：

```css
:root {
  --el-color-primary: #4f46e5;
  --el-color-primary-light-3: #7c74ea;
  /* … light-5 / light-7 / light-8 / light-9 / dark-2 */
}
```

**按钮、标签、分页、单选框、链接、输入框聚焦色会同时变成品牌色** —— 一个变量搞定，不用逐个组件改。

### 为什么要手动覆写"主按钮"

```css
.el-button--primary:not(.is-plain):not(.is-link):not(.is-text) {
  background: var(--ch-gradient);
  box-shadow: 0 6px 16px rgba(79, 70, 229, 0.26);
}
```

把主按钮从**纯色**换成**渐变 + 柔和投影**，这是"高级感"最廉价也最有效的一招。

`:not(.is-plain)` 这些排除条件是必需的 —— 否则会把"朴素按钮""文字按钮"也刷成渐变，反而难看。

### 一个容易踩的坑

`main.js` 里的导入顺序必须是：

```js
import 'element-plus/dist/index.css'   // 先：组件库默认样式
import '@/styles/main.css'             // 后：我们的覆盖
```

**后导入的同名选择器才会生效**。反过来写，覆盖会失效。

## 四、页面编排的三个手法

### 4.1 Hero 区：深色渐变 + 光晕 + 网格

首页、资料库、课程详情都用了同一套结构：

```
深色渐变底  (--ch-gradient-hero)
  + 两个模糊光斑（filter: blur(60px) + 浮动动画）
  + 细网格纹理（background-image 画 1px 线）
  + 顶部对齐的 mask 让网格只出现在左下角
```

**为什么有效**：纯色背景是"平"的，加上光晕后产生了**景深**，
页面立刻从"平面"变成"有空间感"。而网格纹理增加了细节密度，让人感觉精致。

用 `mask-image: radial-gradient(...)` 让网格只出现在某一块，
是为了避免整屏网格显得像工程图纸。

### 4.2 骨架屏（Skeleton）

```html
<div class="ch-skeleton sk-line" style="width: 60%"></div>
```

```css
.ch-skeleton::after {
  transform: translateX(-100%);
  background: linear-gradient(90deg, transparent, rgba(255,255,255,.7), transparent);
  animation: ch-shimmer 1.4s infinite;
}
```

**比"转圈加载"好在哪**：
转圈只告诉用户"在加载"，骨架屏还**预告了内容的版式**。
用户看到"这里马上会出现一张卡片"，心理等待感会短很多。

### 4.3 统一的卡片交互

```css
.ch-card--interactive:hover {
  transform: translateY(-4px);
  box-shadow: var(--ch-shadow-md);
  border-color: rgba(99, 102, 241, 0.35);
}
```

三个动作同时发生：**上浮 + 阴影加深 + 描边染色**。
这是"可交互"的通用视觉语言，用户不用思考就知道"这个能点"。

## 六、响应式与无障碍

### 响应式断点

```
1024px  两栏布局塌成单栏（Hero、统计卡）
900px   登录页隐藏左侧品牌面板
720px   导航栏隐藏副标题与角色文字
600px   筛选栏输入框占满整行、卡片内边距收紧
480px   信息栅格从 3 列 → 1 列
```

### 无障碍（a11y）做了两件事

**① 尊重系统"减弱动态效果"设置**

```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

有前庭功能敏感的用户会在系统里关掉动画，网页应该跟随，而不是强行播放。

**② 键盘焦点可见**

```css
:focus-visible { outline: 2px solid var(--ch-primary); outline-offset: 2px; }
```

用键盘 Tab 导航时能看到焦点框，纯鼠标操作时不会出现多余轮廓（`focus-visible` 的特性）。

## 七、怎么继续扩展（加新页面时的规则）

新增页面时，按这个顺序做，风格就不会跑偏：

1. **不要写死颜色** —— 一律用 `var(--ch-xxx)`，需要新颜色先加令牌
2. **卡片用 `.ch-card`**，可点击的加 `.ch-card--interactive`
3. **标题区用 `.ch-page-head`**，或深色 Hero 结构
4. **加载中给骨架屏**，不要只放 `v-loading` 转圈
5. **空状态给出下一步操作**（`el-empty` 里放一个按钮），不要只写"暂无数据"
6. **列表进场加 `.ch-fade-up`**，并按序号加 `.ch-delay-1~6` 制造错落感
7. **移动端至少检查 600px 宽度下的表现**
