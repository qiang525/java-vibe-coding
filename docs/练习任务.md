## 练习 2 ⭐ 加一个接口

### 目标
实现一个"**我的资料**"接口：`GET /api/resources/mine`，
返回当前登录用户上传的所有资料。

### 你会学到什么
- Controller / Service / Mapper 三层怎么配合加一个新接口
- "服务端注入当前用户 ID"这个安全模式

### 提示

**① 参考现成的写法**

打开 `controller/CourseController.java`，找到 `mine()` 方法：

```java
@ApiOperation("我加入的课程")
@RequireLogin
@GetMapping("/mine")
public Result<PageResult<CourseVO>> mine(CourseQueryDTO query) {
    query.setMemberUserId(UserContext.getUserId());   // ← 关键：服务端注入
    return Result.ok(courseService.pageCourses(query));
}
```

**② 你要做的**

在 `ResourceController` 里加一个**同样结构**的方法，但在 Service 里要：

```java
query.setUploaderId(UserContext.getUserId());   // 强制用当前用户，前端传的会被覆盖
```

> ⚠️ **注意路由顺序问题**：`ResourceController` 已经有 `@GetMapping("/{id}")` 了。
> 如果新加的 `/mine` 被 `/{id}` 抢先匹配，Spring 会尝试把 "mine" 转成 Long 然后报错。
> 想想怎么解决？
>
> （提示：Spring MVC 里**具体路径的优先级高于路径变量**，一般不会冲突，
> 但你可以实测一下，验证这个结论。）

**③ 别忘了**

新接口要加 `@RequireLogin`，否则未登录时 `getUserId()` 会返回 null，
查出来的是"所有 uploader_id 为 null 的资料"（不会有数据，但逻辑是错的）。

### 验收标准
- 用学生的 Token 调 `/api/resources/mine`，只返回他自己传的资料
- 用 admin 的 Token 调，只返回 admin 的
- 未登录调，返回 40101

## 练习 4 ⭐⭐ 数据库：亲手验证索引

### 目标
用 `EXPLAIN` 验证**资料列表查询真的用上了组合索引**，并搞清楚"最左前缀原则"。

### 你会学到什么
- `EXPLAIN` 怎么读
- 组合索引 `(a, b, c)` 为什么 `WHERE b=?` 用不上

### 提示

**① 先看表结构**

打开 `backend/sql/schema.sql`，找到 `resource` 表：

```sql
KEY `idx_course_status_score` (`course_id`, `status`, `score` DESC),
```

**② 在 MySQL 里跑这几条 EXPLAIN**

```bash
export MYSQL_PWD='liuwenqiang123'
mysql -uroot -D coursehub
```

```sql
-- ① 用上索引（course_id 是索引第一列）
EXPLAIN SELECT id, title FROM resource
WHERE course_id = 1 AND status = 'PUBLISHED' ORDER BY score DESC LIMIT 10;

-- ② 只用第三列 → 应该用不上
EXPLAIN SELECT id, title FROM resource WHERE score > 80;

-- ③ 跳过头一列 → 应该用不上
EXPLAIN SELECT id, title FROM resource WHERE status = 'PUBLISHED';
```

**③ 看结果里的三列**

| 列 | 看什么 |
|---|---|
| `key` | 实际用了哪个索引（`NULL` = 没用索引） |
| `type` | `ref` / `range` / `const` 是好现象；`ALL` = 全表扫描 |
| `Extra` | 出现 `Using filesort` 说明排序没走索引 |

**④ 写下来**

在 `docs/` 下新建一个 `我的索引笔记.md`，把这三条 EXPLAIN 的结果和你的理解记下来。

### 验收标准
- 你能说出第 ① 条用了什么索引，第 ②③ 条为什么没用
- 你能解释"最左前缀原则"

## 练习 5 ⭐⭐ 让 Redis 真正派上用场

### 目标
现在的下载次数是**直接更新数据库**的。把这个改成：
**下载次数先累加到 Redis，再由定时任务批量写回数据库。**

### 你会学到什么
- 为什么热点数据要放 Redis
- 定时任务（`@Scheduled`）怎么写

### 提示

**① 为什么要改**

热门资料被频繁下载时，`UPDATE resource SET download_count = download_count + 1`
会对**同一行**反复加锁。并发高的时候，这些请求会排队，数据库压力很大。

**② 你要做的**

**第一：引入 StringRedisTemplate**

```java
@RequiredArgsConstructor
public class ResourceServiceImpl {
    private final StringRedisTemplate redisTemplate;   // Spring 已经配好了 RedisConfig
```

**第二：改下载逻辑**

```java
// 原来的写法（保留，注释掉）
// resourceMapper.increaseDownloadCount(id);

// 新写法：先加到 Redis
String key = Constants.REDIS_DOWNLOAD_COUNT + id;    // 常量已经在 Constants 里定义好了
redisTemplate.opsForValue().increment(key);
```

**第三：写定时任务**

在 `scheduler/` 目录下新建一个类（这个目录目前是空的）：

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class DownloadCountSyncTask {

    @Scheduled(fixedDelay = 60000)   // 每分钟执行一次
    public void sync() {
        // 1. 找出 Redis 里所有的 coursehub:download:* key
        // 2. 把值取出来，更新到数据库
        // 3. 删掉这些 key（避免重复累加）
    }
}
```

> 主启动类上已经有 `@EnableScheduling` 了（M0 就加了），所以 `@Scheduled` 会生效。

**③ 想清楚这两件事**

- 服务重启时，Redis 里还没写回数据库的计数会**丢失**。这个问题严重吗？怎么缓解？
- 如果用 `@Scheduled(fixedDelay)` 和 `@Scheduled(fixedRate)`，有什么区别？

### 验收标准
- 下载一次资料后，Redis 里出现 `coursehub:download:{id}` 这个 key
- 等一分钟后，数据库的 `download_count` 变了
- 你能说清楚"为什么这样能减轻数据库压力"

## 练习 6 ⭐⭐⭐ 挑战：实现"收藏"功能

### 目标
`collection` 表已经建好了但还没有代码。实现**收藏 / 取消收藏 / 我的收藏列表**三个接口。

### 你会学到什么
- 从零加一个完整的业务模块（entity → mapper → service → controller）
- 唯一索引怎么防重复

### 提示

**① 需要新建的文件**（照抄资料模块的结构）

```
entity/Collection.java
mapper/CollectionMapper.java + resources/mapper/CollectionMapper.xml
dto/CollectionQueryDTO.java（可选）
vo/CollectionVO.java（可选）
service/CollectionService.java + impl/CollectionServiceImpl.java
controller/CollectionController.java
```

**② 表结构**

```sql
CREATE TABLE `collection` (
    `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `user_id`     BIGINT UNSIGNED NOT NULL,
    `resource_id` BIGINT UNSIGNED NOT NULL,
    `folder`      VARCHAR(50)     NOT NULL DEFAULT '默认收藏夹',
    `created_at`  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_resource` (`user_id`, `resource_id`),   -- ← 防重复收藏
    KEY `idx_resource` (`resource_id`)
);
```

**③ 三个接口**

| 接口 | 说明 |
|---|---|
| `POST /api/collections/{resourceId}` | 收藏 |
| `DELETE /api/collections/{resourceId}` | 取消收藏 |
| `GET /api/collections` | 我的收藏列表（分页） |

**④ 要处理的两个坑**

- **重复收藏**：先查有没有，有就返回 "已经收藏过了"（参考 `ResultCode.ALREADY_COLLECTED`，
  这个错误码我早就加好了但还没用上）
- **收藏数同步**：`resource.favorite_count` 要跟着 +1 / -1

**⑤ 想清楚**

收藏列表要显示资料标题，你有两个选择：
- 在 `CollectionMapper.xml` 里 JOIN `resource` 表，一次查出来
- 先查收藏，再循环查资料（← 这是 N+1，别这么写）

### 验收标准
- 收藏同一份资料两次 → 第二次返回 40905
- 收藏后 `favorite_count` 增加
- 能查到自己的收藏列表，且**没有 N+1 查询**（可以看 Druid 监控页的 SQL 数量）
