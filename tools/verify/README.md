# tools/verify —— 接口验证脚本

这些脚本用**真实的 HTTP 请求**打后端接口，不是单元测试。
用途：改完代码后快速确认主链路没坏。

## 使用前提

1. 后端已经在跑（`http://localhost:8080`）
2. Redis 在线
3. Python 3.8+（本机用 `C:\Users\liuwe\.workbuddy\binaries\python\versions\3.13.12\python.exe`）

## 四个脚本

| 脚本 | 验证内容 | 会写数据吗 |
|---|---|---|
| `verify_main.py` | 主链路 18 项：静态页、健康检查、接口文档、学院、课程、注册登录、JWT 鉴权、统一错误体 | 会注册 1 个临时账号 |
| `verify_interaction.py` | 17 项：资料详情、下载、收藏、评论（含回复）、举报、版本历史、搜索 | 会写评论/收藏，测试完自动删除 |
| `verify_accounts.py` | 4 个演示账号能否用统一密码登录，管理员接口是否通 | 不写 |
| `reset_demo_data.py` | **重置演示数据**：清空业务表 → 上传 3 个真实文件 → 重算评分 | 会清库！ |

## 怎么跑

### 最常用：确认服务健康

```
cd /d D:\桌面\Java项目AIGC\tools\verify
python verify_main.py
```

输出示例：

```
======================================================================
  CourseHub 整体回归验证
======================================================================
  [PASS] 单端口静态首页 GET / 返回 200   HTTP 200
  [PASS] 健康检查 GET /api/health   {'status': 'UP', ...}
  ...
  结果: 18/18 通过
```

### 重置演示数据（危险，会清空业务表）

```
set MYSQL_PWD=你的MySQL密码
python reset_demo_data.py
```

> 它会：清空 `resource` / `file` / `comment` / `report` 等业务表，
> 删掉 `backend/upload` 下的物理文件，然后重新上传 3 个真实文件（从 `E:\文件办公\` 取）。
> **跑之前确认你不需要现有数据。**

## 关于"通过/失败"的判断

- 全部 `[PASS]` → 主链路正常
- 有 `[FAIL]` → 看后面的 `detail`，通常是断言写错或数据变了，不一定是 bug
  （比如资料数为 0 时，"列表非空"会失败，但这只是没数据）

## 为什么这些不算单元测试

单元测试要隔离数据库和网络，用 Mock 替掉依赖。
这些脚本是**端到端（E2E）验证**：真起服务、真连库、真发请求。
好处是"能跑通就真能用"，坏处是慢、依赖环境。

两者不冲突，正式项目里应该都有（见 `docs/项目体检报告.md` 遗留问题 R7）。
