# tools —— 双击即用的脚本

> 这些脚本是为了**减少你敲命令的次数**。
> 每个脚本干的事都很简单，出问题时可以打开用记事本看它到底做了什么。

---

## 一、最常用的四个

| 脚本 | 什么时候双击 | 成功标志 |
|---|---|---|
| **`check-env.bat`** | 刚接触这个项目 / 觉得环境不对 | 5 项检查逐项打印结果 |
| **`start-redis.bat`** | 每次开机后（第 1 个启动） | 窗口出现 `Ready to accept connections` |
| **`start-backend.bat`** | 每次开机后（第 2 个启动） | 窗口出现 `Started CourseHubApplication` |
| **`git-push.bat`** | 改完代码想传到 GitHub | 提示 `[成功] 已经推送到 GitHub` |

### 标准启动顺序

```
check-env.bat    ← 只在第一次或不放心时跑
      ↓
start-redis.bat  ← 必须跑，窗口最小化别关
      ↓
start-backend.bat← 必须跑，浏览器然后打开 localhost:8080
```

## 三、`verify/` 子目录（可选，进阶）

里面是 4 个 Python 脚本，用真实 HTTP 请求验证后端接口是否正常。
需要 Python 3 环境，**普通使用用不到**。

| 脚本 | 做什么 |
|---|---|
| `verify_main.py` | 主链路 18 项（静态页/健康检查/课程/登录/JWT） |
| `verify_interaction.py` | 17 项（详情/下载/收藏/评论/举报/版本） |
| `verify_accounts.py` | 4 个演示账号能否登录 |
| `reset_demo_data.py` | **重置演示数据**（会清空业务表，慎用） |

详见 `verify/README.md`。

## 四、这些 bat 为什么不能随便改

如果哪天你想改脚本内容，必须先知道这几条（都是踩过坑换来的）：

| 规则 | 违反的后果 |
|---|---|
| **必须用 GBK 编码保存** | UTF-8 会让中文变乱码，甚至闪退 |
| **绝对不能加 `chcp` 命令** | GBK 文件配 `chcp 65001` 会乱码 + 闪退 |
| **`echo` 里不能出现 `>` `<` `\|`** | 会被当成重定向，凭空生成垃圾文件 |
| **少用 `if (...)` 括号块** | 中文写在括号里容易触发解析异常，改用 `goto` |

原因和现场记录见 `../docs/手把手教学/06-故障排查.md` 的 **F01**。

## 五、脚本闪退怎么办

**不要靠双击排查**（窗口一闪就没了看不到错误）。改用命令行：

1. 在本文件夹的地址栏输入 `cmd` 回车
2. 输入脚本名，比如：

```
start-redis.bat
```

3. 回车 —— 这样即使出错，窗口也不会关，你能看到报错
