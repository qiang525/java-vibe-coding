# Java 命令修复工具

## 这个工具解决什么问题

**现象**：在命令行输入 `java -version` 没有正常输出，程序崩溃或报错。

**根本原因**（已诊断确认）：

系统 PATH 的第 1 位是一条失效的旧记录：

```
C:\Program Files\Common Files\Oracle\Java\javapath
```

这是以前安装 Oracle JDK 时留下的「转发器」目录。对应的真身
`C:\Program Files\Java` 已经被删除，所以这个目录里的 `java.exe`
变成了**空壳**——执行它就崩溃（返回码 `0xC0000409`）。

因为它在 PATH 里**排第一位**，系统一找 `java` 就先撞上这个坏文件，
于是：

```
输入 java → 系统按 PATH 顺序找
   第1个：javapath\java.exe    ← 坏了，崩溃  ✗
   ──── 到此为止，后面的根本没机会 ────
   第12个：%JAVA_HOME%\bin      ← 这个是好的，但轮不到它
```

**为什么 Maven 和 IDEA 还能用**：它们不靠 PATH 找 java，而是直接用
`JAVA_HOME` 环境变量的值（现在是 `E:\java\jdk11`），所以不受影响。

## 怎么用

**双击 `run-fix.bat`**

1. 弹出用户账户控制（UAC）→ 点「**是**」
2. 脚本自动执行，显示处理过程
3. 看到「**修复成功！**」即完成
4. 按任意键关闭窗口

**然后必须做**：关闭所有已打开的 CMD / PowerShell 窗口，
并重启 IDEA —— 否则它们还缓存着旧的环境变量。

**验证**：新开一个命令行，执行

```bash
java -version
```

应显示：

```
java version "11.0.5" 2019-10-15 LTS     ← 注意是 11，不是 17
```

## 这个工具做了什么

**只做一件事**：从系统 PATH 中删除那 1 条失效记录。

| 项目 | 说明 |
|---|---|
| 改动范围 | 系统 PATH 中的 22 条 → 21 条，只删 1 条 |
| 其他条目的影响 | **无**，一个都不碰 |
| 是否需要管理员 | 是（系统 PATH 存在 HKLM 注册表，受保护） |
| 是否可撤销 | 是，有自动备份 |

## 安全保障措施

1. **自动备份**：修改前把完整 PATH 存到同目录的
   `PATH_backup_时间戳.txt`
2. **精确匹配**：只删除完全等于目标字符串的那一条，
   不会误伤相似路径
3. **类型保护**：写入时保持 `REG_EXPAND_SZ` 类型。
   这一点很关键——如果写成普通字符串类型，PATH 里的
   `%JAVA_HOME%`、`%SystemRoot%` 这些变量就**不会展开**，
   会导致整个系统的命令大面积失效
4. **写入后校验**：立即读回对比，确认内容、类型、删除结果三项都对
5. **先预览后执行**：可以先跑预览模式看看会改什么

## 预览模式（不改任何东西）

```bash
"E:\python\python.exe" fix_java_path.py --dry-run
```

会显示当前 PATH 状态和将要做的修改，但不执行。

## 文件说明

| 文件 | 作用 |
|---|---|
| `run-fix.bat` | **双击这个**。负责请求管理员权限并调用下面的脚本 |
| `fix_java_path.py` | 实际执行修复逻辑的脚本 |
| `PATH_backup_*.txt` | 自动生成的 PATH 备份（修改前创建） |

## 为什么不能直接帮你改

系统 PATH 存储在 Windows 注册表的 `HKLM`（机器级）分支下，
受系统保护，**必须由管理员权限的进程才能写入**。

作为 AI 助手运行在普通权限下，写入会被系统拒绝。
所以这里提供的是「一键脚本 + 你自己点确认」的方式，
执行动作由你亲自掌控，更安全。

## 诊断依据（备查）

```
javapath\java.exe 执行结果   : rc = 0xC0000409（崩溃）
                             即使复制到别的目录依然崩溃（排除沙箱因素）
C:\Program Files\Java 是否存在: 否（已被删除）
注册表 JavaSoft\Java Runtime Environment : 不存在
注册表 JavaSoft\JDK : 存在 17.0.12 / 26.0.2，但 JavaHome 指向 E:\java

模拟移除该条目后的新进程:
  java -version → 正常返回 11.0.5  ✓
  where java   → 只解析到 E:\java\jdk11\bin\java.exe
```

结论：该条目确为失效残骸，移除后 java 命令恢复正常。
